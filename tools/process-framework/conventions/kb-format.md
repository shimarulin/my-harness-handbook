# Конвенция: формат статей базы знаний (KB)

## Назначение

`content/kb/` — слой фактуры проекта: справочные статьи о методологиях, нотациях, инструментах, принципах. Нарратив и логика выбора — в `content/guide/` (ссылается сюда).

## Каталоги

| Каталог | Содержимое |
|---|---|
| `methods/` | Методологии и нотации: ADR, EARS, BDD, C4/arc42, PRD, RFC |
| `landscape/` | Инструменты и фреймворки: 1 файл = 1 сущность или сравнение |
| `principles/` | Выделенные принципы (из критики и синтеза) |

Реестр всех статей: `meta.yaml` (обязателен для каждой статьи).

## Формат статьи

Язык: русский; устоявшиеся термины не переводятся (ADR, source of truth, durable context).

```markdown
---
id: kb-article-<YYYYMMDD>-<HHMMSSfff>
type: kb-article
status: stub | draft | reviewed
created: YYYY-MM-DD
updated: YYYY-MM-DD
topics: [<topic1>, <topic2>]
author: human:<name> | agent:<name>
freshness_notes: "<маркер актуальности>"
---

# <Название>

| Параметр | Значение |
|---|---|
| Статус | stub / draft / reviewed |
| Обновлено | YYYY-MM-DD |

## Что это
Определение, происхождение, решаемая проблема. 2–5 предложений.

## Ключевые концепции / структура
Суть: составные части, шаблоны, варианты, жизненный цикл.
Плотно, без воды; таблицы предпочтительнее прозы для перечислений.

## Сильные и слабые стороны
Когда работает / когда нет. Ограничения и типичные анти-паттерны.

## Сравнение / выбор
(если применимо) С альтернативами: таблица критериев, матрица «сценарий → рекомендация».

## Источники
- <URL или путь к первоисточнику> — что оттуда взято
- Входные материалы inbox: <пути поглощённых файлов>
```

## Правила

- **Поглощение, не копирование.** Статья пишется заново по источникам; дословно — только шаблоны и таблицы, где форма = суть.
- **Атрибуция обязательна.** Раздел «Источники» — всегда; внешние утверждения — со ссылкой.
- **Свежесть фиксируется.** Поле «Обновлено» + `freshness_notes` в frontmatter и `meta.yaml`.
- **Статусы**: `stub` — каркас с источниками; `draft` — содержательно полна, не вычитана; `reviewed` — вычитана.
- **Маркер актуальности**: «по состоянию на <дата>» для быстро меняющихся тем (SDD-инструменты).

## Связь с meta.yaml

Каждая статья регистрируется в `content/kb/meta.yaml`:

```yaml
- id: kb-article-<YYYYMMDD>-<HHMMSSfff>
  title: <название>
  path: <category>/<file>.md
  status: stub | draft | reviewed
  sources: [<inbox-файлы>]
  last_touched: YYYY-MM-DD
  freshness_notes: "<маркер>"
```

По `sources[]` машинно проверяется покрытие: каждый inbox-файл со статусом `done` должен встречаться хотя бы в одном `meta.yaml`.
