# Конвенция: именование и идентификаторы

## Идентификаторы объектов

Все новые объекты (планы, заметки, research-заметки, drafts) используют формат:

```
<TYPE>-<YYYYMMDD>-<HHMMSSfff>-<slug>.md
```

- `<TYPE>` — тип объекта: `PLAN`, `NOTE`, `RESEARCH`, `DRAFT`, `ADR`.
- `<YYYYMMDD>-<HHMMSSfff>` — время создания **UTC с миллисекундами**.
- `<slug>` — короткое описание (kebab-case).

**Примеры:**
- `PLAN-20261001-164751701-repository-structure.md`
- `NOTE-20261001-170000123-symlinks-vs-moc.md`
- `ADR-20261001-180000456-use-typescript-for-tooling.md`

## Почему UTC с миллисекундами

| Альтернатива | Проблема |
|---|---|
| Последовательная нумерация (`000001`) | Коллизии в разных ветках (оба берут max+1) |
| Время без миллисекунд | Коллизии при двух агентах на одной машине в секунду |
| Локальное время | Неправильная сортировка при разных часовых поясах |
| UUID | Нет читаемости, нет сортировки по имени |
| `<shortid>` после slug'а | Разрушает чистую временную сортировку |

**Миллисекунды** — детерминированная часть времени: сортировка строго хронологическая, коллизия возможна только в одну миллисекунду UTC, разрешается ожиданием следующей миллисекунды.

## Правила slug'а

- kebab-case: lowercase, дефисы, без подчёркиваний.
- Длина: 2–5 слов.
- Описательный: `repository-structure`, не `rs` или `plan1`.
- Без типа в slug'е: `PLAN-...-repository-structure`, не `PLAN-...-plan-repository-structure`.

## Именование директорий

| Паттерн | Где | Пример |
|---|---|---|
| kebab-case | Все директории | `process-framework/`, `research-notes/` |
| `_prefix` | Системные, не трогать вручную | `_objects/` |
| `by-<dimension>/` | Навигационные (симлинки) | `by-topic/`, `by-status/` |
| `YYYY-MM-DD-<slug>/` | Research-заметки | `2026-10-01-orm-selection/` |

## Исключения

- `PLAN-000000__kb-guide-ideas.md` — исторический, сохранён как есть (исключение из правила, зафиксировано в плане).
- Существующие файлы `research/kb/`, `guide/`, `ideas/` — мигрируются с сохранением имён; новые файлы — по новой конвенции.
