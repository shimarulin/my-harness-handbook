# Сравнение решений

**Статус:** черновик | **Дата:** 2026-09 | **Сверить с первоисточниками**

Этот документ содержит детальное сравнение всех исследованных решений
по ключевым критериям, выявленным в процессе анализа.

## Методология сравнения

### Критерии оценки

1. **Функциональность** — возможности для работы с кодом
2. **Агенты и паттерны** — готовые агенты и workflow patterns
3. **Оркестрация** — управление многозадачностью и состоянием
4. **Модели и стоимость** — выбор моделей и оптимизация затрат
5. **Интеграция** — совместимость с инструментами и протоколами
6. **Наблюдаемость** — мониторинг и оценка качества
7. **Гибкость** — возможность кастомизации
8. **Зрелость** — статус проекта и сообщество

### Шкала оценки

| Оценка | Значение |
|---|---|
| ✅✅✅ | Отлично / уникальная возможность |
| ✅✅ | Хорошо |
| ✅ | Базовый уровень |
| ⚠️ | Ограниченно / требует работы |
| ❌ | Отсутствует |

### Общий рейтинг

#### Если нужен **полный контроль**:
1. **Mastra** — полноценный оркестратор, максимальная гибкость
2. **LangGraph** — аналогично, но более low-level
3. **Pi** — модульность и специализация

#### Если нужен **быстрый старт**:
1. **omp** — батареи из коробки, стабильный
2. **OmO Native** — готовые паттерны, автоматическая оптимизация (beta)
3. **Mastra Code** — TUI agent с observational memory
4. **Pi** — просто начать, но дальше строить самому

#### Если нужны **уникальные возможности**:
1. **Oh My Pi** — debuggers, persistent workers, LSP
2. **OmO Native** — category routing, memory
3. **Mastra** — time-travel, Studio

#### Если нужна **стабильность**:
1. **Mastra** — production-ready
2. **LangGraph** — production-ready
3. **Pi / omp** — активное развитие, стабильные релизы

## Матрица выбора

### По типу задачи

| Тип задачи | Лучшее решение | Почему |
|---|---|---|
| **Простой поиск по коду** | Pi + pi-subagents | Готовые инструменты, лёгкий |
| **Исследование + анализ** | OmO Native / omp (workflowz) | explore + librarian / fan-out |
| **Реализация фичи** | OmO Native / omp | ultrawork или plan mode |
| **Отладка бага** | **Oh My Pi** | Debugger support (уникально) |
| **Refactoring** | **Oh My Pi** | LSP integration, atomic edits |
| **Сложный pipeline** | Mastra + omp tools | Полный контроль, snapshots |
| **Multi-agent команда** | OmO Native | Team Mode, category routing |
| **Параллельная работа** | omp / OmO | Worktree isolation |

### По типу команды

| Тип команды | Лучшее решение | Почему |
|---|---|---|
| **Соло-разработчик** | **omp** | Быстрый старт, батареи, стабильный |
| **Небольшая команда** | Pi + Herdr | Модульность, координация |
| **Большая команда** | Mastra + Pi | Полный контроль, observability |
| **AI/ML эксперты** | Mastra / LangGraph | Максимальная гибкость |
| **Обычные разработчики** | OmO Native | Меньше настройки, автоматизация |

### По бюджету

| Бюджет | Лучшее решение | Почему |
|---|---|---|
| **Минимальный** | Pi / omp (MIT) | Бесплатно, открытый код |
| **Средний** | omp + OmO-паттерны | Model roles, hashline |
| **Большой** | Mastra (EE при необходимости) | Enterprise features, поддержка |

## Заключение

Не существует идеального решения для всех случаев. Каждое решение
имеет свои сильные и слабые стороны:

- **Mastra** — для полного контроля, оркестрации и observability
- **Pi** — для модульности и построения собственного стека
- **OmO Native** — для автоматизации и готовых паттернов
- **Oh My Pi** — для уникальных возможностей и производительности
- **Herdr** — для координации нескольких агентов и машин

Выбор зависит от конкретных требований, бюджета, команды и типа задач.
Итоговая рекомендация этого исследования — **omp как основной runtime
+ Mastra для pipelines/observability + Herdr для persistence** —
описана в [16.our-solution.md](16.our-solution.md).
