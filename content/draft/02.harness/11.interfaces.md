## TUI (основной интерфейс)

### Реализация в разных решениях

| Решение | TUI качество | Особенности |
|---|---|---|
| **omp** | ★★★★★ | Native Rust rendering, differential, collab mode |
| **Pi** | ★★★★★ | pi-tui library, tree-structured sessions |
| **senpi** | ★★★★★ | Наследует pi-tui |
| **OmO** | ★★★★ | Через OpenCode TUI (Ultimate) или senpi (Native) |

### Ключевые возможности omp TUI

- **Tool cards**: каждый tool call рендерится как карточка
- **Edit previews**: правки показываются до применения
- **Ask tool**: structured option picker для уточнений
- **Agent Hub** (`Alt+A`): live view всех subagents
- **Session branching**: `/branch` и `/fork` (branch — альтернативная
  ветка той же сессии, fork — новая сессия с текущего состояния)
- **Model switching**: `/model` или `Ctrl+P`

### Herdr integration

```bash
herdr                    # Terminal multiplexer
# В pane: omp            # Ваш агент
# State автоматически отслеживается (working/blocked/idle)
# Переживает закрытие терминала
```

## Web UI

### Вариант 1: Mastra Studio (observability)

```bash
npx create-mastra my-harness
cd my-harness
npm run dev
# Studio: http://localhost:4111
```

**Что даёт:**
- Traces с таймингами каждого шага
- Cost breakdown per model
- Input/output каждого шага
- Time-travel: вернуться к любому шагу, изменить, перезапустить
- История всех запусков

**Ограничения:** не для интерактива (только наблюдение),
требует Mastra workflows (не работает с omp напрямую).

### Вариант 2: omp collab mode (sharing)

```bash
# Внутри omp
/collab
# → ссылка + QR code
# → teammate: omp join <url>
# → или открыть в browser
```

**Что даёт:** live session sharing, read-write (pair programming)
или read-only (observation), client-side encryption, multi-device access.

**Ограничения:** это sharing, не dashboard; нет traces/cost tracking.

### Вариант 3: pi-web (если Pi основной)

```bash
npm install -g @jmfederico/pi-web
pi-web install
pi-web doctor
# Web UI: http://127.0.0.1:8504
```

**Что даёт:** session daemon (переживает disconnect), multi-device
(laptop, phone, tablet), workspaces/git worktrees, встроенные terminals.

**Требования:** Node ≥22.19.0, Pi ≥0.87.0, флаг `--allow-scripts=node-pty`.

**Ограничения:**

- Молодой проект, маленькое сообщество
- Не sandbox (trusted users only)
- Нет observability для LLM calls

### Рекомендация

| Сценарий | Решение |
|---|---|
| Observability для pipelines | **Mastra Studio** |
| Sharing session с коллегой | **omp collab** |
| Persistent web access к Pi | **pi-web** |
| Всё сразу | omp + Mastra (мост через REST API) |

## ACP (Agent Client Protocol)

### Что это

Открытый протокол для связи между IDE и coding agents (аналог LSP,
но для агентов). Разработан Zed, поддерживается JetBrains и другими.

```
IDE (Zed, JetBrains, ...)
    ↕ JSON-RPC 2.0 over stdio
ACP Agent (omp, pi, claude, ...)
```

### Реализация в omp (built-in)

```bash
# Запустить omp как ACP сервер
omp acp
```

**Маппинг инструментов:**

| omp tool | ACP route |
|---|---|
| `bash` | `terminal/create` + `terminal/output` |
| `read` | `fs/read_text_file` |
| `write` | `fs/write_text_file` |
| `edit, bash` | `session/request_permission` |

**Интеграция с Zed:**

```json
// В настройках Zed
{
  "agent_servers": {
    "omp": { "type": "custom", "command": "omp", "args": ["acp"] }
  }
}
```

### Реализация в Pi (через адаптер)

```bash
# Установить адаптер
pi install npm:pi-acp

# Pi теперь доступен как ACP агент
# → pi --mode rpc запускается, bridge к ACP
```

**Ограничения upstream pi-acp:** нет fs/* и terminal/* delegation,
нет session/request_permission gating. Это важно учитывать при
сравнении с нативным `omp acp` (см. таблицу выше).

**Mastra Code как вариант TUI + memory из коробки:** open-source
TUI coding agent (фев 2026), observational memory без compaction,
plan/build modes, LSP, ast-grep, subagents, 1,800 моделей через router.

### Что даёт ACP

- **Чтение буфера**: агент видит файл, который открыт в IDE
- **Запись через save path**: правки идут через editor's save
- **Permission prompts**: подтверждение в IDE UI
- **Terminal integration**: shells в editor's terminal

## Интеграция всех трёх

### Архитектура

```
┌────────────────────────────────────────────────────┐
│ Mastra Server (localhost:4111)                      │
│  ├── Workflows (deterministic pipelines)            │
│  ├── Studio (web UI, observability)                │
│  └── REST API + SSE                                │
└─────────────────┬──────────────────────────────────┘
                  │ HTTP + SSE
                  │
    ┌─────────────┼─────────────┐
    │             │             │
    ▼             ▼             ▼
┌────────┐  ┌────────┐  ┌──────────┐
│ omp    │  │ Browser│  │ IDE      │
│ TUI    │  │(Studio)│  │(via ACP) │
│        │  │        │  │          │
│+ bridge│  │        │  │          │
│extension│  │        │  │          │
└────────┘  └────────┘  └──────────┘
     │
     ▼
┌────────┐
│ Herdr  │
│(runtime)│
└────────┘
```

### Bridge extension для omp → Mastra

```typescript
// extensions/mastra-bridge/index.ts
// (концептуальный пример)

export const mastraBridge = {
  commands: {
    '/workflow': async (args, session) => {
      const [name, ...input] = args.split(' ');

      // 1. Создать run
      const { runId } = await fetch(
        `http://localhost:4111/api/workflows/${name}/create-run`,
        { method: 'POST' }
      ).then(r => r.json());

      // 2. Stream execution
      const response = await fetch(
        `http://localhost:4111/api/workflows/${name}/runs/${runId}/stream`,
        { method: 'POST', body: JSON.stringify({ inputData: input }) }
      );

      // 3. Отображать события в TUI
      for await (const event of parseSSE(response)) {
        session.emit('info', `[${event.stepId}] ${event.status}`);
      }
    }
  }
};
```
