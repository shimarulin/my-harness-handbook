## Классификация решений

### Категория 1: Универсальные оркестрационные фреймворки

**Представители:** Mastra, LangGraph, CrewAI, AutoGen

**Характеристики:** примитивы для любых agent workflows, не заточены
под конкретную предметную область, максимальная гибкость в обмен на complexity.

**Когда выбирать:** нужен полный контроль, команда имеет AI/ML экспертизу,
требования уникальны, готова долгосрочная поддержка.

### Категория 2: Специализированные coding agent harness

**Представители:** Pi (Earendil Works), OmO Native, Oh My Pi (omp.sh)

**Характеристики:** заточены под разработку ПО, готовые агенты и инструменты,
быстрый старт, меньше гибкости.

**Когда выбирать:** нужен быстрый результат, требования стандартны,
команда не хочет строить всё с нуля.

### Категория 3: Инфраструктурные компоненты

**Представители:** Herdr, Temporal, Docker sandbox

**Характеристики:** решают конкретную задачу, не являются harness,
используются в комбинации.

### Herdr — herdrdev/herdr

**См. полный анализ в [09.herdr.md](09.herdr.md).**

Краткая сводка: always-running server, state tracking, multi-machine

### LangGraph — langchain-ai/langgraph

**Что это:** Фреймворк для stateful, multi-step AI workflows.

| Характеристика | Значение |
|---|---|
| Графы | Stateful, conditional edges, loops, nested subgraphs |
| Persistence | Checkpointing |
| Python + JS | Оба языка |
| Зрелость | Production-proven |

**Сильные стороны:** максимальная выразительность для сложных графов,

**Слабые стороны:** менее batteries-included чем Mastra, нет Studio,
нет built-in web UI.

**Дополнение:** LangChain продвигает **Deep Agents** — higher-level
пакет поверх LangGraph (планирование, subagents, файловая система).
Это снимает часть претензии «нет batteries-included»; LangGraph
остаётся low-level слоем.

## Эволюция ландшафта

### Тренд 1: Специализация

Ранние решения (LangGraph, CrewAI) были универсальными.
Новые решения (OmO, omp) заточены под coding agents.
Даже фреймворк (Mastra) выпустил собственного coding-агента — тренд усилился.

**Причина:** универсальные решения требуют слишком много работы
для создания production-ready coding agent.

### Тренд 2: Multi-model orchestration

Раньше: одна модель для всех задач.
Сейчас: разные модели для разных задач с автоматическим routing.

**Причина:** оптимизация стоимости и качества.

### Тренд 3: Observability как first-class citizen

Раньше: logging как afterthought.
Сейчас: встроенные traces, costs, evals.

**Причина:** без observability система деградирует.

### Тренд 4: IDE интеграция

Раньше: только CLI.
Сейчас: ACP, MCP, IDE extensions.

**Причина:** разработчики работают в IDE, не в терминале.

### Тренд 5: Determinism vs LLM

Раньше: всё через LLM.
Сейчас: детерминированные проверки + LLM только где нужно.

**Причина:** снижение стоимости и повышение надёжности.
