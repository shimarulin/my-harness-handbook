# Herdr: детальный анализ

**Статус:** Активно развивается  
**Сайт:** https://herdr.dev  
**Документация:** https://herdr.dev/docs/  
**Тип:** Terminal multiplexer для AI агентов

> **Фаундер:** Can Celik (ogulcancelik), YC F26. **Лицензия:** Apache-2.0
> (перелицензировано с AGPL в авг 2026). **Текущая версия:** v0.9.0
> (сверить; v0.7.1 — июнь 2026). Single Rust binary с vendored Ghostty VT.

## Позиционирование

Herdr — это не оркестратор и не агент. Это **терминальный сервер**,
который управляет терминалами для других агентов. Позиционируется
как "always running" мультиплексор с поддержкой множества агентов
и машин.

**Ключевая идея:** Дать разработчику единое место для управления
всеми агентами, независимо от того, какой агент используется.

## Что такое Herdr

### Не является:

- ❌ Оркестратором (не управляет логикой workflow)
- ❌ Агентом (не выполняет задачи)
- ❌ Моделью (не использует LLM)
- ❌ Фреймворком (не предоставляет API для агентов)

### Является:

- ✅ Terminal multiplexer (как tmux, но для агентов)
- ✅ Session manager (persistent sessions)
- ✅ Agent monitor (tracking status)
- ✅ Multi-machine coordinator (SSH support)

### Entry Points

#### 1. CLI

```bash
herdr              # интерактивный режим
herdr start <agent> # запустить агента
herdr status       # статус всех агентов
herdr machine add workbox  # добавить машину
```

#### 2. Socket API

По документации Herdr: для скриптов и простой автоматизации начинайте
с CLI-обёрток; raw socket API — для custom-интеграций и долгоживущих
event-подписок.

```bash
herdr socket "pane split"
herdr socket "agent list"
```

#### 3. Web Dashboard

```bash
herdr dashboard
```

**Показывает:** все агенты, их статус (working, blocked, idle), логи,
resource usage.

## Ключевые возможности

### 1. Always Running

**Проблема:** Закрываете ноутбук — агенты умирают.

**Решение:** Herdr работает как сервер в фоне.

```bash
# Запускаете агентов в Herdr
herdr start pi
herdr start claude-code
herdr start omp

# Закрываете ноутбук
# Агенты продолжают работать

# Открываете снова
herdr attach
# Всё на месте
```

### 2. Agent State Monitoring

Herdr читает каждый терминал и определяет статус агента:

| Статус | Что значит |
|---|---|
| **working** | Агент активно работает |
| **blocked** | Агент ждёт ввод от пользователя |
| **idle** | Агент завершил работу, ждёт команду |

```bash
herdr status

# Вывод:
claude-code    working    2m 15s
pi             blocked    waiting for approval
omp            idle       last command: 5m ago
```

### 3. Multi-Machine Support

```bash
herdr machine add workbox
herdr machine add remote-server --ssh user@host
herdr machines

# Вывод:
local      connected    3 agents
workbox    connected    2 agents
remote     connected    1 agent
```

**Возможности:** все агенты в одном интерфейсе, переключение между
машинами, независимые reconnect, единый agent list.

### 4. Agent-Native API

CLI и socket API — это одна и та же поверхность:

```bash
herdr pane split
herdr agent start claude-code
herdr agent prompt claude-code "review this"
```

**Что это даёт:** агенты могут спавнить других агентов, отправлять
запросы друг другу, ждать, пока другой разблокируется; не нужно
эмулировать клавиатуру.

### 5. Поддержка 22+ агентов из коробки

**Поддерживаются:** Claude Code, Codex, Pi, OpenCode, Cursor, Grok,
Copilot, Hermes и другие.

**Что это значит:** не нужно настраивать, работает сразу, правильное
определение статуса, интеграция из коробки.

> pi-intercom умеет открывать Herdr project pane при отправке сообщения
> в другой кодбейз (openProjectPaneIfMissing) — живой пример
> agent-native API в действии.

## Конфигурация

### Основные команды

```bash
# Сессии
herdr attach          # подключиться
herdr detach          # отключиться
herdr status          # статус

# Агенты
herdr start <agent>   # запустить
herdr stop <agent>    # остановить
herdr list            # список

# Машины
herdr machine add <name>     # добавить
herdr machine remove <name>  # удалить
herdr machines               # список

# Панели
herdr pane split      # разделить
herdr pane close      # закрыть
herdr pane focus      # фокус
```

### Конфигурация

```yaml
# ~/.config/herdr/config.yml

theme: dark
scrollback: 10000
notifications: true

machines:
  - name: local
    type: local
  - name: workbox
    type: ssh
    host: user@workbox.local

agents:
  pi:
    command: pi
    cwd: ~/projects
  omo:
    command: omo
    cwd: ~/projects
```

## Интеграция с другими решениями

### Herdr + Pi

```bash
herdr start pi
```

**Преимущества:** persistent sessions, multi-machine support,
мониторинг статуса, единый интерфейс.

### Herdr + OmO Native

```bash
herdr start omo
```

**Особенности:** omo-herdr-dag создаёт side pane через Herdr API,
использует `herdr pane split --ratio 0.65`, автоматическое открытие
при workflow DAG, синхронизация состояния.

### Herdr + Oh My Pi

```bash
herdr start omp
```

**Особенности:** omp работает в Herdr pane, Agent Hub показывает статус,
можно мониторить все агенты.

### Пример: Несколько агентов

```bash
# Terminal 1: Herdr dashboard
herdr dashboard

# Terminal 2: Несколько агентов
herdr start pi              # для code exploration
herdr start omo             # для implementation
herdr start claude-code     # для review

# Все видны в одном месте
# Статус каждого агента
# Можно переключаться
```

## Сильные стороны

### 1. Решает реальную проблему

Управление несколькими агентами сложно. Единый интерфейс для всех.
Меньше контекстных переключений, легче отслеживать статус,
можно работать параллельно.

### 2. Не заменяет агентов

Работает с любыми агентами. Можно использовать любимый агент,
не нужно менять стек, можно комбинировать разные агенты,
легко мигрировать.

### 3. Persistent Sessions

Агенты живут в фоне. Долгие задачи завершаются, можно отойти
от компьютера, ничего не теряется при перезагрузке, resume после crash.

### 4. Multi-Machine

Единый интерфейс, не нужно открывать несколько терминалов,
легко переключаться, масштабируемость.

### 5. Agent-Native API

Агенты могут управлять друг другом. Возможна автоматизация,
агенты могут координироваться, программный контроль.

### 6. Mouse-First UX

Не нужно учить keyboard shortcuts. Легко начать, интуитивно,
как в обычном терминале, меньше ошибок.

## Слабые стороны

### 1. Не является оркестратором

Не управляет логикой workflow. Не заменяет полноценный harness,
нужно использовать вместе с другим решением, добавляет слой сложности.

### 2. Не управляет моделями

Не выбирает модели, не оптимизирует стоимость. Это ответственность
агента, нужно решать отдельно.

### 3. Не предоставляет агентов

Только инфраструктура. Нужны другие решения для агентов,
нет готовых инструментов, нет готовых паттернов.

### 4. Дополнительный слой

Может быть избыточным для простых задач. Больше компонентов,
больше точек отказа, сложнее отлаживать, нужно поддерживать.

## Когда использовать Herdr

### Используйте, если:

- ✅ Работаете с несколькими агентами одновременно
- ✅ Нужны persistent sessions
- ✅ Работаете на нескольких машинах
- ✅ Нужен мониторинг статуса агентов
- ✅ Хотите единый интерфейс
- ✅ Долгие задачи, нельзя прерывать

### Не используйте, если:

- ❌ Используете один агент
- ❌ Короткие задачи
- ❌ Не нужны persistent sessions
- ❌ Работаете только на одной машине
- ❌ Хотите минимализм

## Пример сценария

```bash
# Утро понедельника
herdr start pi              # для исследования кода
herdr start omo             # для реализации
herdr start claude-code     # для ревью

# Работаете в Herdr
# Pi исследует auth модуль
# OmO реализует feature
# Claude Code ревьюит изменения

# Обед — закрываете ноутбук
# Агенты продолжают работать

# Возвращаетесь
herdr attach
# Всё на месте

# Вечер — все задачи завершены
herdr status
# Все idle, можно завершать
```

## Выводы

Herdr — это **инфраструктурный компонент**, который решает проблему
управления несколькими агентами.

**Главное преимущество:** Единый интерфейс для всех агентов с
persistent sessions и multi-machine support.
**Главный недостаток:** Не является полноценным решением, нужно
использовать вместе с другим harness.
**Лучше всего подходит для:** Команд, которые используют несколько
агентов и нуждаются в координации и мониторинге.
**Не рекомендуется для:** Простых сценариев с одним агентом.
