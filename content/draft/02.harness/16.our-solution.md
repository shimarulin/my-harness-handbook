## Компоненты и их роли

| Компонент | Роль | Когда используется |
|---|---|---|
| **omp** | Основной инструмент: 90% daily work | Всегда |
| **Herdr** | Persistence + state tracking | Когда работа > 30 минут |
| **Mastra** | Pipelines + observability | Для repeatable workflows |
| **Mastra Studio** | Web dashboard | Для анализа cost/traces |

## Установка

### Минимальный setup (omp only)

```bash
# 5 минут до первого агента
curl -fsSL https://omp.sh/install | sh
omp setup    # Импортирует из .claude, .cursor, etc.
omp          # Запуск
```

### Полный setup (рекомендуемый)

```bash
# 1. omp — основной runtime
curl -fsSL https://omp.sh/install | sh
omp setup

# 2. Herdr — persistence
curl -fsSL https://herdr.dev/install.sh | sh

# 3. Mastra — pipelines + observability (когда понадобится)
npx create-mastra my-harness
cd my-harness
npm run dev  # Studio: localhost:4111
```

## Конфигурация

### omp: model roles

```yaml
# ~/.omp/agent/config.yml
modelRoles:
  default: anthropic/claude-opus-5      # Основная работа
  smol: xai/grok-4-fast                 # Дешёвый fan-out
  slow: openai/gpt-6-sol                # Deep reasoning
  plan: anthropic/claude-fable-5-1      # Планирование
  advisor: xai/grok-4-fast              # Watchdog

retry:
  fallbackChains:
    default:
      - anthropic/claude-opus-5
      - openai/gpt-6-sol
      - kimi/k3
    smol:
      - xai/grok-4-fast
      - deepseek/v4-flash
```

### Herdr: запуск omp

```bash
# Herdr запущен, omp в pane
herdr
# В pane: omp

# Или через socket API
herdr pane run w1:p1 "omp"
```

### Mastra: workflow для критичных цепочек

```typescript
// src/mastra/workflows/code-review.ts
import { createWorkflow, createStep } from '@mastra/core';
import { z } from 'zod';

export const codeReviewWorkflow = createWorkflow({
  inputSchema: z.object({ query: z.string() }),
  outputSchema: z.object({
    issues: z.array(z.any()),
    summary: z.string()
  })
})
  .then(classifyStep)      // groq/llama-4-scout
  .then(scoutStep)         // omp через subprocess: grep + ast-grep
  .parallel([
    analyzeStep,            // anthropic/claude-opus-4-5
    verifyStep             // без LLM: тесты
  ])
  .then(verdictStep)
  .commit();
```

## Что нужно дописать (gap analysis)

| Компонент | Что нужно | Объём работы |
|---|---|---|
| **omp ↔ Mastra bridge** | Extension для вызова Mastra workflows из omp TUI | ~200-400 строк TS |
| **omp ↔ Mastra Code bridge** | Альтернатива omp ↔ Mastra workflows: вызов Mastra Code как subprocess для memory-задач | Оценить до написания |
| **Cost tracking в omp** | Если omp не экспортирует costs → bridge к Mastra | Средний |
| **Custom tools** | Доменные инструменты поверх omp | По мере надобности |

## Риски и миграции

### Риск: omp — fork, зависимость от can1357

**Mitigation:** omp — MIT license, можно fork. Pi (upstream) — fallback
с extension ecosystem.

### Риск: Mastra — framework, не tool

**Mitigation:** Mastra workflows — это TypeScript код, живёт в вашем
репо. Можно заменить на LangGraph без потери workflow definitions.

### Риск: Быстрая эволюция экосистемы

**Mitigation:** Стек построен на модульных компонентах. Замена любого
не ломает остальные.

## Альтернативы (если это решение не подойдёт)

| Если... | То... |
|---|---|
| Нужен максимальный model routing | OmO Native вместо omp |
| Нужен максимум контроля | Mastra + Pi (вместо omp) |
| Нужен минимализм | Pi + pi-subagents |
| Python предпочтительнее | LangGraph + любой executor |
| Нужен maximum automation | OmO Native + Herdr |
| Готовы к beta ради автоматизации | OmO Native как основной |
| **Приоритет — memory без compaction** | **Mastra Code** (observational memory, единый вендор) |

> Примечание: omp = Oh My Pi — debuggers уже входят в рекомендуемый
> стек, отдельная альтернатива не требуется.

## Итоговая рекомендация

**Основной стек:**
- **omp** — как daily driver
- **Herdr** — для persistence и multi-machine
- **Mastra** — для repeatable pipelines и observability

**Почему именно так:**
1. omp — самое мощное специализированное решение с уникальными
   возможностями (debuggers, persistent workers, LSP).
2. Herdr — решает проблему persistence без замены агентов.
3. Mastra — даёт observability и детерминированные workflows
   там, где они критичны.

**Что даёт вместе:**
- 90% daily work — omp с TUI, ACP, memory, workflowz.
- Long-running tasks — Herdr с persistent sessions.
- Critical pipelines — Mastra с Zod schemas и Studio.
