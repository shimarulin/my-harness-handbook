# Mastra: детальный анализ

**Статус:** Production-ready, активно развивается  
**Репозиторий:** https://github.com/mastra-ai/mastra  
**Stars:** 28k (сентябрь 2026)  
**Лицензия:** Apache 2.0 (core, включая Studio); отдельные enterprise-функции в `ee/` — под enterprise license

## Позиционирование

Mastra — это современный TypeScript фреймворк для построения AI-приложений
и агентов. Позиционируется как "the easiest way to build, tune, and scale
reliable AI products".

**Ключевая идея:** Предоставить production-ready primitives для agent
orchestration с хорошей developer experience.

## Mastra Code (февраль 2026)

**Mastra Code** (`npm i -g mastracode`) — open-source TUI coding agent,
выпущенный 24 февраля 2026. Ключевая особенность: **observational memory**,
которая «никогда не компактирует» — сжимает контекст без потери информации.

**Под капотом:** Mastra + pi-tui + LibSQL (локально, ничего не покидает машину).
Использует Agent, Memory, Workspace, Tools, Model Router, MCP-примитивы фреймворка.

**Возможности:**
- Plan mode + build mode
- LSP интеграция, ast-grep (структурные правки одним правилом)
- Subagents (в т.ч. модели, отличные от основной)
- Worktrees, OAuth для Claude Max/ChatGPT Plus
- 1,800 моделей через model router
- Skills support

> Mastra Code — прямой конкурент omp/OmO в категории «специализированный
> coding harness». Это снимает главный аргумент «Mastra не заточена под
> coding agents» и одновременно усиливает тезис «Mastra = слой
> оркестрации/observability».

## Архитектура

### Основные концепции

#### 1. Workflows

Декларативный workflow engine с типизированными шагами:

```typescript
import { createWorkflow, createStep } from "@mastra/core";
import { z } from "zod";

const step1 = createStep({
  id: "step-1",
  inputSchema: z.object({ query: z.string() }),
  outputSchema: z.object({ result: z.string() }),
  execute: async ({ inputData }) => ({ result: inputData.query })
});

const workflow = createWorkflow({
  inputSchema: z.object({ query: z.string() }),
  outputSchema: z.object({ result: z.string() })
})
  .then(step1)
  .commit();
```

**Возможности:**
- `.then()` — последовательное выполнение
- `.parallel()` — параллельное выполнение (результаты доступны по id шагов)
- `.branch()` — условные переходы
- `.dowhile()` — циклы с условием
- `suspend()` / `resume()` — пауза для human-in-the-loop (вызывается
  внутри `execute` шага, возобновление через API)
- Snapshots — persist across restarts

> ⚠️ API Mastra активно развивается. Синтаксис выше соответствует
> исследованию сентября 2026 — перед использованием сверяйтесь с
> [актуальной документацией](https://mastra.ai/docs).

#### 2. Agents

Автономные агенты с tool calling:

```typescript
const agent = new Agent({
  name: "code-reviewer",
  instructions: "Review code for bugs and style issues",
  model: openai("gpt-4o"),
  tools: [readFile, grep, runTests]
})
```

**Возможности:** model routing (40+ провайдеров), tool calling,
memory (conversation history), observational memory.

#### 3. Tools

```typescript
const readFile = createTool({
  id: "read-file",
  description: "Read file contents",
  inputSchema: z.object({ path: z.string() }),
  outputSchema: z.object({ content: z.string() }),
  execute: async ({ inputData }) => {
    return { content: await fs.readFile(inputData.path, "utf-8") };
  }
});
```

#### 4. Mastra Studio

Веб-интерфейс для управления агентами, workflows, traces:

```bash
npm run dev
# Открывается на http://localhost:4111
```

**Возможности:** визуализация workflows, просмотр traces, cost breakdown,
eval results, управление agents. Входит в открытую часть (Apache 2.0).

#### 5. Server API

Mastra автоматически экспонирует workflows через REST с SSE streaming:

```bash
# Создать run
POST /api/workflows/:id/create-run

# Запустить с streaming
POST /api/workflows/:id/runs/:runId/stream

# Возобновить suspended
POST /api/workflows/:id/runs/:runId/resume

# Time-travel: вернуться к шагу и перезапустить
POST /api/workflows/:id/runs/:runId/time-travel
```

## Ключевые возможности

### 1. Model Routing

Единый интерфейс для **600+ моделей** (framework) / **1,800 моделей**
(Mastra Code через model router), формат `"provider/model-name"`:

```typescript
const agent = new Agent({
  model: "groq/llama-4-scout",       // дешёвая для поиска
  // model: "anthropic/claude-opus-4-5",  // дорогая для анализа
});
```

**Поддерживаемые провайдеры:** OpenAI, Anthropic, Google, Mistral,
Together, Fireworks, Groq, Cerebras, Azure, AWS Bedrock, Google Vertex,
Ollama, LM Studio, llama.cpp, OpenRouter и многие другие. Fallback на
уровне приложения при сбое провайдера.

### 2. Observability

Встроенная observability из коробки. Автоматическое логирование всех
operations. Интеграция с LangSmith, Langfuse, Arize Phoenix.

**Что отслеживается:** traces каждого workflow run, cost breakdown
по моделям, token usage, tool call success/failure, latency.

### 3. Evals

```typescript
// ⚠️ API Mastra 1.0 мог измениться. Сверить с docs.mastra.ai
import { evaluate } from "@mastra/evals";
const results = await evaluate({
  data: testCases,
  agent: myAgent,
  metrics: [accuracy, relevance, completeness]
});
```

### 4. Human-in-the-loop

Suspend/resume для human approval. `suspend()` вызывается внутри
`execute` шага; workflow приостанавливается, snapshot сохраняется;
возобновление — через REST API с `resumeData`:

```typescript
const approvalStep = createStep({
  id: "approval",
  execute: async ({ inputData }) => {
    if (needsApproval(inputData)) {
      return suspend({ reason: "confirm-destructive-action" });
      // Workflow приостановлен; snapshot сохранён
      // → POST /runs/:runId/resume { resumeData: { approved: true } }
    }
    return { approved: true };
  }
});
```

### 5. Integrations

```typescript
// Next.js
export default function Agent() {
  const { messages, input, handleInputChange } = useMastraAgent();
  // ...
}

// Express / Hono / Fastify — server adapters
app.post("/agent", mastraHandler(myAgent));
```

## Архитектурные паттерны

### Simple Chain

```typescript
const workflow = createWorkflow({ inputSchema, outputSchema })
  .then(step1)
  .then(step2)
  .then(step3)
  .commit();
```

### Conditional Branching

```typescript
const workflow = createWorkflow({ inputSchema, outputSchema })
  .then(classifyStep)
  .branch(
    (state) => state.category,
    { simple: simplePath, complex: complexPath }
  )
  .commit();
```

### Parallel Execution

```typescript
// Результаты parallel-шагов доступны по их id в inputData следующего шага
const workflow = createWorkflow({ inputSchema, outputSchema })
  .parallel([searchStep, analyzeStep, validateStep])
  .then(mergeResultsStep)
  .commit();
```

### Retry Loop

```typescript
const workflow = createWorkflow({ inputSchema, outputSchema })
  .then(attemptStep)
  .branch(
    (state) => state.success,
    { true: doneStep, false: attemptStep }
  )
  .commit();
```

## Пример использования для Coding Agent

### Задача: Investigation workflow

```typescript
import { createWorkflow, createStep } from "@mastra/core";
import { z } from "zod";

const searchStep = createStep({
  id: "search",
  inputSchema: z.object({ query: z.string() }),
  outputSchema: z.object({
    files: z.array(z.string()),
    evidence: z.array(z.any())
  }),
  execute: async ({ inputData, mastra }) => {
    const agent = mastra.getAgent("search-agent");
    return await agent.generate(inputData.query);
  }
});

const analyzeStep = createStep({
  id: "analyze",
  inputSchema: z.object({
    files: z.array(z.string()),
    evidence: z.array(z.any())
  }),
  outputSchema: z.object({
    summary: z.string(),
    confidence: z.number()
  }),
  execute: async ({ inputData, mastra }) => {
    const agent = mastra.getAgent("analyst-agent");
    return await agent.generate(`Analyze: ${JSON.stringify(inputData)}`);
  }
});

const judgeStep = createStep({
  id: "judge",
  inputSchema: z.object({
    summary: z.string(),
    confidence: z.number()
  }),
  outputSchema: z.object({
    sufficient: z.boolean(),
    followup: z.string().optional()
  }),
  execute: async ({ inputData }) => ({
    sufficient: inputData.confidence > 0.8,
    followup: inputData.confidence < 0.8 ? "Need more details" : undefined
  })
});

const investigationWorkflow = createWorkflow({
  inputSchema: z.object({ query: z.string() }),
  outputSchema: z.object({
    sufficient: z.boolean(),
    followup: z.string().optional()
  })
})
  .then(searchStep)
  .then(analyzeStep)
  .then(judgeStep)
  .commit();
```

**Что видно:** Mastra даёт структуру, но всю логику нужно писать самому.
Нет готовых инструментов для кода. Нужно интегрировать с Pi/omp или
другими tools.

## Интеграция с Pi

```typescript
import { createTool } from "@mastra/core";
import { ReadTool, GrepTool } from "@earendil-works/pi-agent-core/tools";

const piRead = createTool({
  id: "pi-read",
  description: "Read file using Pi optimized reader",
  inputSchema: z.object({ path: z.string() }),
  outputSchema: z.object({ content: z.string() }),
  execute: async ({ inputData }) => {
    const tool = new ReadTool();
    return tool.execute({ path: inputData.path });
  }
});

const piGrep = createTool({
  id: "pi-grep",
  description: "Search files using Pi grep",
  inputSchema: z.object({ pattern: z.string(), path: z.string().optional() }),
  outputSchema: z.object({ matches: z.array(z.any()) }),
  execute: async ({ inputData }) => {
    const tool = new GrepTool();
    return tool.execute(inputData);
  }
});
```

**Преимущества:** используем готовые Pi tools, Mastra управляет orchestration.
**Недостатки:** два слоя, сложнее отлаживать, нужно поддерживать интеграцию.

Альтернатива — запуск omp в one-shot режиме как subprocess:

```typescript
import { spawn } from "child_process";

const ompStep = createStep({
  execute: async ({ inputData }) => {
    const proc = spawn("omp", ["-p", inputData.instruction]);
    // Сбор stdout, JSON-результат
  }
});
```

## Сильные стороны

### 1. Production-Ready
Зрелое решение с хорошей документацией, активное сообщество (28k stars),
регулярные обновления.

### 2. Developer Experience
Типизация (TypeScript), Zod-контракты между шагами с compile-time
проверкой, hot reload в dev mode.

### 3. Observability
Встроенная observability, интеграция с популярными платформами,
cost tracking, eval framework, time-travel debugging.

### 4. Flexibility
Можно строить любые workflows, полный контроль над состоянием,
custom tools и agents, интеграция с любыми сервисами.

### 5. Ecosystem
Интеграция с React/Next.js, MCP servers, Vercel AI SDK, CopilotKit.

## Слабые стороны

### 1. Не заточен под Coding Agents

**Проблема (устарело с фев 2026):** фреймворк по-прежнему не поставляет
coding-агента из коробки в core, но с февраля 2026 существует отдельный
продукт **Mastra Code**.

**Актуальная ситуация:** для solo-разработчика evaluation стоит начинать
с Mastra Code, а workflows/Studio остаются ценностью фреймворка.

**Следствия:** core-фреймворк всё ещё требует написания агентов с нуля;
Mastra Code даёт готовый harness с memory из коробки, но это отдельный
продукт, а не часть core.

### 2. Высокий порог входа

Нужно понимать concepts (workflows, agents, tools, state). Время на
изучение, сложность для новичков, больше boilerplate кода.

### 3. Enterprise-функции платные

Core и Studio открыты (Apache 2.0), но отдельные enterprise-функции
в `ee/`-директории требуют лицензии. Для solo-использования core
обычно достаточно.

### 4. Complexity

Для простых задач Mastra может быть overkill.

## Когда выбирать Mastra

### Выбирайте Mastra, если:

- ✅ Нужен полный контроль над workflows
- ✅ Команда имеет TypeScript экспертизу
- ✅ Важна observability из коробки
- ✅ Нужен веб-интерфейс (Studio)
- ✅ Планируется интеграция с веб-приложениями
- ✅ Требования уникальны и не покрываются готовыми решениями

### Не выбирайте Mastra, если:

- ❌ Нужен быстрый старт
- ❌ Нет времени строить всё с нуля
- ❌ Требования стандартны для coding agents
- ❌ Команда не имеет AI/ML экспертизы
- ❌ Нужны готовые агенты и инструменты

> Для быстрого старта с готовым coding-агентом рассмотрите **Mastra Code**.

## Выводы

Mastra — это **зрелый production-ready фреймворк** для agent orchestration
с хорошей developer experience и observability.

**Главное преимущество:** Полный контроль, типизированные контракты
и observability.
**Главный недостаток:** Не заточен под coding agents, требует много работы.
**Лучше всего подходит для:** Команд, которые хотят строить custom harness
с нуля и имеют для этого ресурсы; как слой observability поверх omp.
**Не рекомендуется для:** Быстрого старта или когда нужны готовые решения.
