# Маршрутизация моделей

**Статус:** черновик | **Дата:** 2026-09

## Проблема

Разные задачи требуют разного «уровня интеллекта» модели:

| Задача | Оптимальная модель | Стоимость |
|---|---|---|
| Поиск по коду (grep) | Дешёвая + быстрая | $0.05/1M tokens |
| Классификация intent | Дешёвая | $0.05/1M tokens |
| Анализ кода | Дорогая + reasoning | $15/1M tokens |
| Генерация кода | Средняя | $3/1M tokens |
| Review | Дорогая | $15/1M tokens |

Использование одной дорогой модели для всего — **расточительно**.

## Подходы к routing

### 1. Per-Role (omp)

omp определяет **10 ролей**, каждая со своей моделью:

```yaml
# ~/.omp/agent/config.yml
modelRoles:
  default: anthropic/claude-opus-5      # Основная работа
  smol: xai/grok-4-fast                 # Дешёвый fan-out
  slow: openai/gpt-6-sol                # Deep reasoning
  plan: anthropic/claude-fable-5-1      # Планирование
  commit: deepseek/v4-flash             # Commit messages
  vision: openai/gpt-5.6-asta           # Изображения
  designer: anthropic/claude-sonnet-5   # UI работа
  task: custom-model                    # Subagent workers
  advisor: xai/grok-4-fast              # Watchdog
  tiny: kimi/flash                      # Ultra-cheap
  web: gemini/gemini-3-flash            # Web-поиск
  image: openai/gpt-image-1             # Генерация изображений
  speech: openai/tts-1                  # Синтез речи
  dictation: openai/whisper-1           # Распознавание речи
  judge: anthropic/claude-sonnet-5      # Оценка качества
  memory: xai/grok-4-fast               # Memory operations
```

> Ролей стало ~14: добавлены web, image, speech, dictation, judge,
> memory с ordered fallbacks по ролям.

**Использование:**

```bash
omp --smol "search for TODO comments"     # использует grok-4-fast
omp --slow "design auth architecture"     # использует gpt-6-sol
```

### 2. Per-Step (Mastra)

Каждый шаг workflow явно указывает модель:

```typescript
const workflow = createWorkflow({
  inputSchema: z.object({ query: z.string() })
})
  .then(createStep({
    id: 'classify',
    execute: async ({ inputData }) => {
      return callLLM({
        model: 'groq/llama-4-scout',      // ← дешёвая
        prompt: buildClassifyPrompt(inputData)
      });
    }
  }))
  .then(createStep({
    id: 'analyze',
    execute: async ({ inputData }) => {
      return callLLM({
        model: 'anthropic/claude-opus-4-5', // ← дорогая
        prompt: buildAnalysisPrompt(inputData)
      });
    }
  }))
  .commit();
```

### 3. Per-Category (OmO)

OmO категоризирует задачи и маршрутизирует по category:

```
task(category: "ultrabrain")     → GPT-6 Astra max
task(category: "deep")           → GPT-6 Astra high
task(category: "quick")          → GPT-5.6 Luna Fast
task(category: "visual-engineering") → Claude Fable 5.1 max
task(category: "writing")        → Claude Fable 5.1
```

**Актуальный список категорий (README OmO):** visual-engineering,
ultrabrain, deep + deep-high/deep-low, quick, artistry, writing,
unspecified-low/high.

> Модельные маппинги меняются между релизами — срез на сентябрь 2026.

### 4. Fallback Chains (omp, OmO)

При 429 / quota / недоступности — следующая модель в цепочке:

```yaml
# omp: ~/.omp/agent/config.yml
retry:
  fallbackChains:
    default:
      - anthropic/claude-opus-5
      - openai/gpt-6-sol
      - kimi/k3
    smol:
      - xai/grok-4-fast
      - deepseek/v4-flash
      - claude-haiku-4.5
```

```
Запрос → claude-opus-5 → 429 → fallback → gpt-6-sol → OK
```

### 5. Path-Scoped Models (omp)

Разные модели для разных репозиториев:

```yaml
enabledModels:
  - path: ~/work/enterprise-project
    models: [anthropic/claude-opus-5]    # только дорогая
  - path: ~/side-projects
    models: [xai/grok-4-fast, kimi/k3]  # только дешёвые
```

## Cost Optimization Techniques

### 1. Kibitzer / Advisor Pattern

Дешёвая модель предотвращает дорогие ошибки:

```
Main agent ($15/1M)          Advisor ($0.05/1M)
    │                              │
    │ plan change                  │ watch
    │                              │ read memory
    │ skip test                    │ judge
    │                              │
    ▼                              ▼
  [потенциально $500 баг]     "Last time this broke
                               production. Run test first."
    │                              │
    ▼                              │
  [course-correct, save $500]      │
```

**Стоимость advisor:** ~$0.01 на turn
**Предотвращённый ущерб:** потенциально сотни долларов

### 2. Hashline Edits (omp)

Content-hash anchors вместо перепечатки строк:

| Метрика | До | После | Экономия |
|---|---|---|
| Grok 4 Fast output tokens | 100% | 39% | **−61%** |
| Retry на bad diffs | частые | редкие | время + токены |

Источник: README omp (benchmaxxed-таблица). Полная таблица: Grok Code
Fast 1 — 6.7%→68.3% на edit-задачах; Gemini 3 Flash — +5pp к str_replace;
Grok 4 Fast — −61% output tokens; MiniMax — 2.1× pass rate.

Десятки последовательных вызовов collapse в один:

```
БЕЗ absorption:
  read(file1) → read(file2) → read(file3) → ... → read(file20)
  20 round trips, 20 раз контекст отправляется

С absorption:
  [все 20 reads в одном шаге]
  1 round trip, контекст отправляется 1 раз
```

### 4. Compaction (senpi, omp)

Адаптивное сжатие контекста:

```
Context Window: 200k tokens

Before compaction: [195k...approaching limit]
  ↓ adaptive threshold triggered
After compaction:  [45k...summarized, key facts preserved]
  ↓ продолжение работы
```

### 5. Round-Robin Credentials (omp)

Несколько API keys на провайдера:

```yaml
providers:
  anthropic:
    keys:
      - sk-ant-1...
      - sk-ant-2...
      - sk-ant-3...
```

## Сравнение подходов

| Критерий | omp (roles) | Mastra (per-step) | OmO (categories) |
|---|---|---|---|
| **Гранулярность** | Per-role | Per-step | Per-category |
| **Гибкость** | ★★★★ | ★★★★★ | ★★★★ |
| **Fallback** | ✓ | Вручную | ✓ |
| **Cost tracking** | ★★ | ★★★★★ | ★★★ |
| **Ease of use** | ★★★★★ | ★★★ | ★★★★ |
| **Определяется** | Config file | В коде | Автоматически |

## Рекомендация

1. **Daily work**: omp с настроенными model roles
2. **Repeatable pipelines**: Mastra с per-step routing в коде
3. **Exploratory**: OmO с automatic category routing
