# Отказоустойчивость

**Статус:** черновик | **Дата:** 2026-09

## Уровни отказоустойчивости

```
Уровень 4: Machine      → Herdr multi-machine federation
Уровень 3: Process      → Herdr session daemon, pi-web daemon
Уровень 2: Workflow     → Mastra snapshots, suspend/resume
Уровень 1: Model call   → Fallback chains, retry policies
Уровень 0: Tool call    → Timeouts, circuit breakers
```

## Уровень 0: Tool calls

### Timeouts (omp, senpi)

```yaml
# omp
tools:
  bash:
    timeout: 30s         # default
    maxTimeout: 300s     # maximum allowed
```

senpi имеет `bash-timeout` builtin extension: default + max-timeout
enforcement, policy в system prompt.

### Circuit Breakers (pi-fabric)

```typescript
// pi-fabric guardrails
{
  "guardrails": {
    "timeouts": { "default": 30_000 },
    "concurrency": { "max": 10 },
    "recursionDepth": { "max": 64 },
    "costBudgets": { "maxPerRun": 5.00 }  // $5 max per run
  }
}
```

## Уровень 1: Model calls

### Fallback chains (omp, OmO)

```
anthropic/claude-opus-5
    ↓ 429 (rate limit)
openai/gpt-6-sol
    ↓ 503 (service unavailable)
kimi/k3
    ↓
deepseek/v4-flash
    ✓
```

**omp:**

```yaml
retry:
  fallbackChains:
    default:
      - anthropic/claude-opus-5
      - openai/gpt-6-sol
      - kimi/k3
```

**OmO:** аналогичные chains per-category в `packages/senpi-task/src/agents/builtin/fallback-chains.ts`

### Retry policies

**Mastra:** `StreamErrorRetryProcessor` — автоматический retry для
transient LLM API и stream failures, с built-in matching для
OpenAI/Anthropic stream error patterns.

## Уровень 2: Workflows

### Mastra snapshots

```typescript
// Workflow приостанавливается
const workflow = createWorkflow({
  inputSchema: z.object({ ... })
})
  .then(step1)
  .then(step2)      // ← suspend здесь
  .then(step3)      // ← не выполнен
  .commit();

// Snapshot сохраняется:
// - результаты каждого завершённого шага
// - оставшиеся retry attempts
// - suspend/resume payloads
// - общий state

// После перезапуска:
// resume с шага 2, не с начала
```

**Storage:** настраиваемый provider (PostgreSQL, LibSQL, in-memory).
Snapshots переживают deployments и application restarts.

### Suspend / Resume (Mastra)

```typescript
const approvalStep = createStep({
  execute: async ({ inputData }) => {
    if (needsHumanApproval) {
      return suspend({ reason: 'confirm-destroy-action' });
      // Workflow приостановлен
      // Human решает
      // → resume({ resumeData: { approved: true } })
    }
    return proceed();
  }
});
```

### Time-travel (Mastra)

```bash
# Вернуться к шагу 2, изменить input, перезапустить
POST /workflows/:id/runs/:runId/time-travel
{
  "stepId": "step-2",
  "inputData": { ... modified ... }
}
```

### В omp

omp не имеет workflow-level snapshots. Session trees позволяют
branching, но это не то же самое:

| Возможность | Mastra | omp |
|---|---|---|
| Snapshot workflow state | ✓ | ✗ |
| Resume с конкретного шага | ✓ | ✗ |
| Time-travel (rewind + retry) | ✓ | ⚠️ частично (session-level rewind через checkpoint/rewind) |
| Session branching | ✗ | ✓ (`/branch` / `/fork`) |
| Compaction (context) | ✗ | ✓ |

> У omp появились checkpoint/rewind инструменты (session-level rewind,
> не workflow snapshots) — смягчает разрыв между подходами.

## Уровень 3: Process

### Herdr session daemon

```
┌─────────────────────────────────────────┐
│ Herdr Server (background daemon)        │
│                                         │
│  Terminal 1: omp (agent working)        │
│  Terminal 2: tests (running)            │
│  Terminal 3: build (background)         │
│                                         │
│  ← Все переживают:                      │
│     - Закрытие terminal client           │
│     - Обрыв SSH                          │
│     - Перезагрузку (restore on boot)    │
└─────────────────────────────────────────┘
```

**Что даёт:**
- Терминалы живут в background server
- Agent state tracking: working/blocked/idle/done
- Restart машины → Herdr восстанавливает layout и сессии

### pi-web session daemon

Аналогично для web UI: session daemon держит Pi сессии живыми,
браузер — просто окно.

## Уровень 4: Machine

### Herdr machine federation

```bash
# Локальная машина + удалённый сервер
herdr machine add workbox    # desktop upstairs
herdr machine add cloud-vm   # rented server

# В одном UI:
# - Workspaces с обеих машин
# - Agents на обеих машинах
# - Переключение без открытия новых клиентов
# - Работа продолжается когда вы offline
```

**Trust model:** credentials остаются на каждой машине. Gateway
проксирует requests, не копирует auth.

## Сравнение fault tolerance

| Уровень | omp соло | omp + Herdr | omp + Herdr + Mastra |
|---|---|---|---|
| Tool timeouts | ✓ | ✓ | ✓ |
| Model fallbacks | ✓ | ✓ | ✓ |
| Process persistence | ★★ (sessions) | ★★★★★ | ★★★★★ |
| Workflow snapshots | ✗ | ✗ | ★★★★★ |
| Suspend/resume | ✗ | ✗ | ★★★★★ |
| Machine federation | ✗ | ✓ | ✓ |
| Time-travel | ✗ | ✗ | ★★★★★ |

## Рекомендация

1. **Минимум**: omp с настроенными fallback chains
2. **Стандарт**: omp + Herdr (persistence + state tracking)
3. **Полный**: omp + Herdr + Mastra (для критичных workflows с snapshots)
