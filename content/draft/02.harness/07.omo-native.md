## senpi: движок OmO Native

### Что это

senpi — **opinionated fork pi-mono** от code-yeongyu (автора OmO).
Не OmO-специфичный проект: это отдельный fork, созданный как «light
version of OMO», который можно использовать standalone.

> «senpi is a senpai-name pun and a more **sane** pi with extra
> batteries included»

### Отношение к Pi

senpi наследует все пакеты pi-mono:

```
senpi (fork)
├── @earendil-works/chord          (application composition)
├── @earendil-works/pi-telemetry   (telemetry contracts)
├── @earendil-works/pi-ai          (unified LLM API)
├── @earendil-works/pi-agent-core  (agent runtime)
├── @earendil-works/pi-coding-agent (CLI)
├── @earendil-works/pi-tui         (terminal UI)
└── + 18 builtin extensions        (добавлено senpi)
```

**Модификации core минимизированы** и отслеживаются в changes.md файлах
рядом с каждой изменённой директорией — для reviewable upstream merges.

### Влияние OmO на senpi

| OmO feature | senpi builtin |
|---|---|
| IntentGate | Keyword detection (ultrawork/ulw, team, hyperplan) |
| Todo Enforcer | todowrite + continuation loop |
| Per-model tuning | prompt-preset (GPT-5.x, Claude, Kimi presets) |
| Session recovery | compaction (adaptive, emergency) |
| Apply-patch on GPT | gpt-apply-patch (Codex-style) |
| Permission system | permission-system (opencode-style) |

### Чего senpi НЕ содержит (по дизайну)

| OmO feature | Причина отсутствия |
|---|---|
| Discipline Agents (Sisyphus, etc.) | Слишком тяжело для single binary |
| Team Mode | Требует opencode plugin architecture |
| ultrawork / ulw | OmO-specific orchestration |
| Hashline | Стандартный edit достаточно |
| Skill system | Skills как first-class — OmO concept |
| Ralph Loop / ulw-loop | Self-referential, тяжёлый |

## Category-Based Routing

### Концепция

Вместо ручного выбора моделей, OmO автоматически выбирает модель
на основе категории задачи.

```typescript
task({
  category: "ultrabrain",
  prompt: "Solve this complex algorithm problem"
});
// OmO автоматически выбирает: GPT-6 Astra max → GPT-5.6 Sol max → fallback
```

### Встроенные категории

| Категория | Назначение | Модель (по умолчанию) |
|---|---|---|
| `ultrabrain` | Hard logic, architecture | GPT-6 Astra max |
| `deep` | Deep work, research | GPT-6 Astra high |
| `visual-engineering` | UI/UX, frontend | Claude Fable 5.1 max |
| `architect` | Design consultation | Claude Fable 5.1 max |
| `quick` | Single-file changes, typos | GPT-5.6 Luna Fast |
| `artistry` | Creative work | Claude Fable 5.1 |
| `writing` | Documentation, prose | Claude Fable 5.1 |
| `unspecified-low` | Low-effort fallback | MiMo V2.6 Pro |
| `unspecified-high` | High-effort fallback | Claude Opus 5 |

### Fallback Chains

```
Запрос → claude-opus-5 → 429 → fallback → gpt-6-sol → OK
```

Каждая категория имеет свою цепочку приоритета:

```typescript
const categoryChains = {
  ultrabrain: [
    "openai/gpt-6-astra:max",
    "openai/gpt-5.6-sol:max",
    // fallback to next available
  ],
  quick: [
    "openai/gpt-5.6-luna-fast:low",
    "deepseek/v4-flash:low",
    // fallback
  ]
};
```

**Как работает:** пробует первую модель в цепочке; при недоступности
(rate limit, down) — следующую; логирует skipped rungs.

## Curated Агенты

### Встроенные read-only агенты

#### 1. explore

**Назначение:** Быстрая разведка кодовой базы  
**Модель:** GPT-5.6 Luna Fast (cheap, fast)  
**Tools:** grep, glob, read

#### 2. librarian

**Назначение:** Поиск документации и OSS кода  
**Модель:** GPT-5.6 Luna Fast  
**Tools:** websearch, context7, grep_app

#### 3. plan-consultant

**Назначение:** Gap analysis перед планированием  
**Модель:** Claude Opus 5  
**Доступность:** Только во время `/ulw-plan`

#### 4. plan-reviewer

**Назначение:** Валидация work plan  
**Модель:** GPT-6 Astra  
**Доступность:** Только во время `/ulw-plan`

### Kibitzer

**Назначение:** Memory sidecar для накопления знаний.

**Особенности:** read-only (не пишет memory), может только nudges,
bounded/redacted events, self-checking.

## Workflow Patterns

### ultrawork / ulw

**Назначение:** Автоматическое выполнение задачи.

```
User: ultrawork implement auth token refresh

OmO:
1. Explores codebase (explore agent)
2. Researches patterns (librarian agent)
3. Implements feature (worker with ultrabrain category)
4. Verifies with diagnostics
5. Keeps working until done
```

### /ulw-plan

**Назначение:** Interview-based планирование.

```
User: /ulw-plan implement auth token refresh

OmO (Planner):
1. Asks clarifying questions
2. Identifies scope and ambiguities
3. Fans out research (explore + librarian)
4. Brings in plan-consultant for gap analysis
5. Brings in plan-reviewer for validation
6. Generates decision-complete work plan
```

### /ulw-execute

**Назначение:** Выполнение approved work plan.

**Options:** `--worktree <path>`, `--make-pr`, `--ship`
(⚠️ опция `--ship` упоминается в ранних черновиках и не проверена по
первоисточникам — перед использованием сверьтесь с документацией OmO).

### Team Mode

**Назначение:** Параллельная работа нескольких агентов.

> Beta включает **Memory system + CodeMode + Anthropic subscription auth**.

```
User: team-mode on

OmO:
1. Lead agent + up to 8 parallel members
2. Real-time tmux visualization
3. Shared mailbox
4. Shared task list
5. Dedicated team_* tools
```

**Встроенные patterns:**

- **hyperplan** — 5 hostile critics, debate в parallel
- **security-research** — 3 hunters + 2 PoC engineers

## Memory System

### Letta-Code Style

```typescript
/remember "Auth service uses JWT with 24h expiry"
/memory                    # view memory
/search "auth patterns"    # search memory
/reflect                   # background reflection
```

### Background Reflection ("Dreaming")

Event-triggered (step-count or compaction), spawns DETACHED senpi -p child,
uses omo quick category, git worktree isolation, hard deadline.

## DAG Viewer (omo-herdr-dag)

**Репозиторий:** https://github.com/jc01rho/omo-herdr-dag

Установка: `npx omo-herdr-dag@latest install`. Использование: `/dag-pane`.

**Возможности:** node states (running/pending/completed/failed),
dependencies, task details (model, progress, elapsed), interactive
controls (`↑`/`↓` scroll, `←`/`→` switch runs, `Tab` select, `Space`
expand/collapse, `d` toggle full details, `q` close).

## Сильные стороны OmO Native

- Автоматическая оптимизация стоимости (category routing)
- Готовые workflow patterns (ultrawork, /ulw-plan, /ulw-execute, team mode)
- Memory system с background reflection
- Curated агенты (4 готовых)
- DAG viewer (omo-herdr-dag)
- Большое сообщество (69k stars)
- 54+ lifecycle hooks

## Слабые стороны OmO Native

- Beta channel (может быть нестабильно)
- Opinionated (сложнее кастомизировать)
- Нет ACP из коробки
- Нет debuggers
- Нет persistent workers
- Сложность (54+ hooks, много features)
- **Bus-фактор:** проект позиционируется как personal side project,
  поддерживается Jobdori (Dori); риск выше, чем у omp/Pi

## Когда выбирать OmO Native

### Выбирайте, если:

- ✅ Нужна автоматическая оптимизация стоимости
- ✅ Нужны готовые workflow patterns
- ✅ Важна memory system
- ✅ Нужен DAG viewer
- ✅ Хотите быстрый старт
- ✅ Доверяете opinionated решениям

### Не выбирайте, если:

- ❌ Нужен production-ready (не beta)
- ❌ Нужна максимальная гибкость
- ❌ Нужна ACP интеграция
- ❌ Нужны debuggers
- ❌ Нужны persistent workers
