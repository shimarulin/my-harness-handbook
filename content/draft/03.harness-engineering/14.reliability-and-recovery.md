## 1. Таксономия отказов и первый ответ системы

| Отказ | Признак | Первый ответ |
|---|---|---|
| Транспортный сбой API | Ошибки сети/429/5xx | Retry с backoff; не тратить итерацию агента |
| Невалидный вызов инструмента | Схема отклонила аргументы | Ошибка-подсказка с допустимыми значениями ([11.3.1](./11.tool-engineering.md)) |
| Провал gate | Тесты/линтер/judge | Фидбек-цикл с дефект-листом ([02.5](./02.orchestration-patterns.md)) |
| Переполнение контекста | Usage у порога | Компакция по политике (§3) |
| Залипание/треш | §4 | Лестница интервенций (§4) |
| Крэш процесса | Падение harness | Resume от чекпоинта (§2) |
| Дрейф scope | Правки вне `files_owned` | Watchdog: diff против плана → ревью |

Ключевой принцип: **отказы разных классов обрабатываются разными, заранее определёнными механизмами**, а не «модель как-нибудь разберётся».

## 2. Уровни чекпоинтинга

| Уровень | Механизм | Восстановление |
|---|---|---|
| **Turn-level** | Append-only журнал событий (JSONL): каждый LLM-вызов, tool call, результат | Replay/resume с последнего шага |
| **Node-level** | Снапшоты состояния графа (LangGraph checkpointer) | Продолжение с узла |
| **Durable execution** | Temporal / Inngest: event-sourcing, ретраи, таймеры ([07.3.4](./07.selection-guide.md)) | Продолжение workflow после падения машины |
| **Repo-level** | Git: ветка задачи, WIP-коммиты на принятых шагах (паттерн Aider) | Diff-based undo, откат к шагу |
| **Artifact-level** | Blackboard-артефакты ([02.4](./02.orchestration-patterns.md)) | Воркеры рестартуют **от артефактов**, не от транскриптов ([05.6.1](./05.memory-and-knowledge.md)) |

**Правило:** чекпоинт — это состояние, из которого можно продолжить **без реконструкции из памяти**. Всё, что нужно для продолжения, должно лежать в артефактах или журнале.

## 3. Политика компакции

- Порог: ~80% usage ([03.6](./03.context-engineering.md), п. 7).
- Что сохраняется дословно: утверждённые решения, интерфейсы, открытые вопросы, свидетельства верификации, next-step; остальное — суммаризация ([03.3.3](./03.context-engineering.md)).
- **Компакция на границах фаз**, не внутри критического цикла: компакция меняет префикс → cache miss ([03.3.5](./03.context-engineering.md)); на границе фаз кэш и так перестраивается.
- Не компактировать посреди evaluator-цикла: теряются refined_queries и счётчик попыток.

---

## 4. Залипание: детекция и лестница интервенций

**Эвристики детекции:**
- одинаковые tool+args ≥ N раз подряд;
- провал gate с одинаковой причиной ≥ 2 раз;
- контекст растёт, а gate-статус не меняется;
- число итераций превышает запланированное для узла.

**Лестница интервенций (от дешёвой к дорогой):**
1. Инжекция подсказки (hint) без смены контекста.
2. Смена модели на шаге (эскалация, [04.4](./04.economics-and-cost.md)).
3. Respawn свежего воркера с брифом из артефактов ([05.6.4](./05.memory-and-knowledge.md)).
4. Перепланирование ([12.6](./12.planning-and-decomposition.md)).
5. Эскалация человеку + отчёт о состоянии.

---

## 5. Лестница самокоррекции (от дешёвого к дорогому)

1. **Детерминированный фидбек** — тест + stack trace дословно в контекст: бесплатно и максимально информативно (self-debugging: модель читает ошибку исполнения и правит).
2. **Triage дешёвой моделью** — структурированный «что сломалось и почему» из сырого лога; кодеру идёт структура, не лог.
3. **Повтор той же модели** с фидбеком — ограничено счётчиком ([02.6](./02.orchestration-patterns.md)).
4. **Сильная модель** — после двукратного провала дешёвой ([04.4.1](./04.economics-and-cost.md)).
5. **Fresh-context respawn** — когда контекст «отравлен» попытками ([05.6.4](./05.memory-and-knowledge.md)).
6. **Reflexion-память** — «что не сработало и почему» прикладывается к следующей попытке; **только верифицированные факты** (лог тестов), не догадки. *Академический источник: Reflexion (Shinn et al., 2023) — сверить.*

---

## 6. Kill criteria и graceful degradation

- Бюджеты на задачу и узел: токены, wall time, итерации ([02.6](./02.orchestration-patterns.md)).
- При исчерпании: **best-effort артефакт + явный отчёт о нерешённом**; запрет «тихих» частичных результатов.
- Работа в ветке задачи; merge — только после всех gates (права — [01.sandbox](../01.sandbox/README.md), permission gates — [06.2.5](./06.harness-architecture.md)).
- Stop hook: агент завершается не по своей воле, а по подтверждению gates внешним кодом ([02.5.3](./02.orchestration-patterns.md)).

## 7. Побочные эффекты и идемпотентность

- Инструменты записи проектировать идемпотентными; поддерживать dry-run.
- `apply_patch` — атомарный: применён целиком или не применён; иначе полусостояния.
