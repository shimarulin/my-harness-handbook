## 1. Критерии выбора

| Критерий | Что важно |
|---|---|
| **Язык** | Python vs TypeScript vs Rust |
| **Контроль оркестрации** | Граф vs supervisor vs handoffs |
| **Изоляция контекста** | Subagent-as-tool vs shared state |
| **Зрелость** | Production-ready vs experimental |
| **Вендор-лок** | Открытый vs проприетарный |
| **Экосистема** | LangSmith, MCP, интеграции |
| **Стоимость** | Лицензия, hosting, токены |

## 3. Рекомендации по сценариям

### 3.1. «Мне нужен полный контроль над графом и чекпоинтами»

**Выбор: LangGraph.**

**Обоснование:**
- Самый зрелый state-machine / graph runtime.
- Checkpointing, resume после падений.
- LangSmith для tracing.
- Большая экосистема.

**Стек:** Python + LangGraph + FastAPI + PostgreSQL + pgvector + Docker + Langfuse.

### 3.2. «Я хочу остаться в TypeScript»

**Выбор: Mastra или Pi + custom.**

**Mastra:**
- TypeScript-native.
- `createWorkflow` с `.then/.branch/.parallel/.dountil`.
- First-class OpenTelemetry tracing.

**Pi + custom:**
- Minimal agent turn.
- SDK для встраивания.
- Полный контроль над hooks.

**Стек:** TypeScript + Mastra / Pi + Inngest + PostgreSQL + pgvector + Docker + OpenTelemetry.

### 3.3. «Мне нужен быстрый прототип»

**Выбор: CrewAI.**

**Обоснование:**
- Простая ментальная модель: roles, tasks, tools.
- Быстро собрать демо.
- Хорошо для команд без глубокой инфраструктуры.

**Недостатки:** меньше контроля над состоянием и ветвлениями.

### 3.4. «Мне нужен production с долговременными workflow»

**Выбор: LangGraph + Temporal / Inngest.**

**Обоснование:**
- Temporal: долговременные workflow, ретраи, replay, таймеры, signals, human approval.
- Inngest: event-driven functions, меньше инфраструктуры.

**Схема:**
```
Temporal управляет жизненным циклом задачи
  ├─ SearchActivity
  ├─ JudgeActivity
  ├─ CodegenActivity
  ├─ SandboxTestActivity
  └─ Approval
```

### 3.5. «Я хочу готовый SWE-стек»

**Выбор: Claude Agent SDK или OpenHands.**

**Claude Agent SDK:**
- Те же инструменты, что у Claude Code.
- Subagents, hooks, MCP.
- Проприетарно (Anthropic).

**OpenHands:**
- MIT.
- Docker sandbox.
- Event-driven architecture.
- Agent Canvas.

### 3.6. «Мне нужна максимальная кастомизация»

**Выбор: Pi + custom hooks.**

**Обоснование:**
- Minimal agent turn.
- SDK для встраивания.
- Extensions API.
- MIT.
- Полный контроль над Context Engineering.

## 4. Комбинирование фреймворков

### 4.1. LangGraph + Claude Agent SDK

**Схема:**
- LangGraph: оркестрация цепочек, conditional edges.
- Claude Agent SDK: инструменты для работы с кодом.

**Преимущества:** полный контроль над графом + готовый SWE-стек.

### 4.2. Pi + Mastra

**Схема:**
- Pi: runtime агентов.
- Mastra: workflow engine.

**Преимущества:** TypeScript-native, workflow-graph, полный контроль.

### 4.3. LangGraph + Temporal

**Схема:**
- Temporal: durable execution.
- LangGraph: агентные цепочки внутри activities.

**Преимущества:** production-grade надёжность + гибкость графа.

---

## 5. Что не рекомендуется

### 5.1. OpenCode как основа для SDLC-оркестратора

**Проблемы:**
- Context engineering слабее Cursor/Pi. 199K+ stars , но context engineering недостаточно развит.
- Prompt caching хрупкий (подтверждённый баг с DeepSeek API).
- HN-критика: brittle prompt caching, тяжёлые ресурсы, opinionated system prompts.

**Вердикт:** приятный CLI, но не основа для кастомного SDLC-оркестратора.

### 5.2. Claude Managed Agents / Agent SDK как единственная основа

**Проблема:** вендор-лок на модель и инфраструктуру.

### 5.3. Переписывание runtime с нуля

**Проблема:** Pi / OpenHands / Codex уже решают то, что вы бы писали месяцами.

## 6. Сравнение по Terminal-Bench

| Агент + Модель | Terminal-Bench 2.1 |
|---|---|
| GPT-5.6 Terra + Codex | 78.4%  |
| Claude Opus 5 + Terminus 2 | 78.9%  |
| Gemini 3.7 Flash + mini-SWE-agent | 11.1%  |

| GLM-5.3 | 41.8%  |

**Экономика прогона (важно для выбора):** полная стоимость прогона TB 4.0 различается вдвое при почти равном качестве: GPT-6 Astra — **1.5B токенов / $3.3k** при 58.2%, Claude Fable 5.1 — **2.7B / $6.2k** при 57.9%, Claude Opus 5 — **6.5B / $6.0k** при 51.8%. Дорогая модель + дорогой harness ≠ лучший результат за доллар — прямая иллюстрация тезиса [15](./15.efficiency-framework.md) про измерение cost per phase и model routing.

**Вывод:** модель важнее harness. Один и тот же агент даёт разные результаты на разных моделях. Поэтому harness без вендор-лока с возможностью подменять модели — правильный выбор.

## 7. Практический план внедрения

### Этап 0: Определить рамки

- Какие типы задач первыми?
- Нужен ли автоматический PR?
- Можно ли агенту писать код?
- Можно ли запускать команды?
- Нужен ли human approval?
- Локальный запуск или облако?

### Этап 1: Минимальный investigation harness

Цель: поиск + проверка достаточности.

Компоненты:
- репозиторий;
- индексация;
- SearchAgent;
- SufficiencyJudge;
- отчёт;
- логирование.

### Этап 2: Артефакты и трейсинг

- PostgreSQL;
- хранение отчётов;
- версии цепочек;
- стоимость;
- trace id;
- повторный запуск.

### Этап 3: Планирование и код

- Planner;
- Coder;
- Git branch;
- patch generation;
- diff review.

### Этап 4: Песочница и тесты

- Docker;
- запуск тестов;
- линтеры;
- typecheck;
- сбор логов;
- автоматическая проверка патча.

### Этап 5: Eval

- 20–50 золотых задач;
- метрики;
- регрессионные прогоны;
- сравнение версий промптов;
- сравнение моделей.

### Этап 6: Production

- Temporal/Inngest;
- rate limits;
- secrets management;
- RBAC;
- audit log;
- approval gates;
- cost alerts.

## 9. Итоговая рекомендация

Для задач разработки ПО с фиксированными цепочками под тип задач и evaluator-loop:

1. **Оркестрация:** LangGraph (Python) или Mastra/Pi (TypeScript).
2. **Durable execution:** Temporal или Inngest (когда нужен production).
3. **Поиск по коду:** гибридный tree-sitter + ripgrep + embeddings + reranker.
4. **Артефакты:** PostgreSQL + object storage.
5. **Исполнение:** Docker sandbox.
6. **Наблюдаемость:** Langfuse/OpenTelemetry.
7. **Оценка:** собственный набор реальных задач + метрики.
8. **Вдохновение:** OpenHands, SWE-agent, Aider, SWE-bench.
