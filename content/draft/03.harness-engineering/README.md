## Аннотация

Этот раздел — теоретико-архитектурный справочник по проектированию продвинутых harness для разработки ПО. Он нужен, чтобы выбирать среди альтернатив и собирать вместе наиболее эффективные для своего круга задач решения. Комбинации решений, механик и архитектур не всегда дают ожидаемый эффект, поэтому мы не отбрасываем варианты, о которых мало знаем, но явно отмечаем, какие решения могут быть неэффективны.

**Что такое эффективность в контексте этого раздела:** решение той же задачи за меньшую стоимость и/или меньшее время. Или незначительное увеличение времени при существенном снижении стоимости. Или выполнение задачи более дешёвой моделью. Или значительное повышение качества без значительного роста общих затрат — например, большую часть работы выполняют более слабые и дешёвые модели, а критические участки проходят с более сильными.

## Навигация по документам

### [01. Landscape: ландшафт и классификации](./01.landscape.md)

Определение harness, его границы и отличия от смежных понятий. Пять классификаций паттернов (Anthropic, Azure, Google, Andrew Ng, академическая таксономия). Сравнение основных подходов.

**Ключевые вопросы:** Что такое harness? Чем workflow отличается от агента? Какие классификации паттернов существуют и как они соотносятся?

### [02. Orchestration Patterns: паттерны оркестрации](./02.orchestration-patterns.md)

Детальный разбор паттернов: prompt chaining, routing, parallelization, orchestrator-workers, evaluator-optimizer, supervisor, hierarchical, blackboard. Когда использовать workflow vs agent. Conditional edges, quality gates, max iterations.

**Ключевые вопросы:** Как построить цепочку поиск → анализ → критика → цикл? Когда нужен детерминированный граф, а когда — свободный агент?

### [03. Context Engineering: контекст и механики](./03.context-engineering.md)

Изоляция контекста субагентов, progressive disclosure, skills, tool response → файлы, фазовая загрузка MCP, суммаризация на артефактах, prompt caching. Context rot, lost-in-the-middle, attention dilution.

**Ключевые вопросы:** Как не забивать контекст основного агента? Как бороться с деградацией качества при росте контекста?

### [04. Economics and Cost: экономика и стоимость](./04.economics-and-cost.md)

Token economics: 4× для агентов, 15× для мультиагентных систем. Каскадирование моделей, model routing по типу задач. Prompt caching (90% скидка на чтение). Кэширование артефактов. Измерения и телеметрия.

**Ключевые вопросы:** Как снизить стоимость без потери качества? Где тратятся токены и как это измерить?

### [05. Memory and Knowledge: память и знания](./05.memory-and-knowledge.md)

Типы памяти (краткосрочная, долгосрочная, процедурная). Обзор решений: Mem0, Zep/Graphiti, Letta, Cognee, Hindsight. ADR и база знаний паттернов. Графовые и векторные базы для контекста проекта.

**Ключевые вопросы:** Как сохранять контекст между сессиями? Как развернуть базу знаний на каждой машине?

## Ключевые принципы

1. **Простейшее решение сначала.** Workflow с детерминированными шагами — если задачу можно нарисовать как блок-схему. Agent — только когда нужна динамическая адаптация.

2. **Изоляция контекста — главный рычаг эффективности.** Субагенты получают только задачу, возвращают только итог. Сырые данные → во внешнее хранилище.

3. **Типизированные артефакты на границах.** Pydantic/zod-схемы на каждом хедоффе. Ошибка ловится на границе, а не тянется дальше.

4. **Quality gates обязательны.** Цикл завершён ≠ задача выполнена. Детерминированные проверки → LLM-judge с рубрикатором.

5. **Max iterations — жёсткий предохранитель.** Критик-цикл без счётчика — главная причина исчерпания бюджета.

6. **Модель под роль.** Дешёвая на поиск/суммаризацию, сильная на планирование/критику. Каскадирование: cheap-first, escalate-on-failure.

7. **Телеметрия с первого дня.** Cost per phase, cache hit rate, context growth, качество per cost. Без этого все оптимизации — гадания.

8. **Не переписывать runtime.** Pi / OpenHands / Codex как основа. Свой слой — только оркестрация и context engineering.
