## 1. Типы памяти

| Тип | Горизонт | Назначение | Пример |
|---|---|---|---|
| **Краткосрочная (working)** | В рамках сессии | Текущий контекст, tool outputs | Session context |
| **Долгосрочная (persistent)** | Между сессиями | Решения, интерфейсы, прогресс | Project state |
| **Процедурная** | Постоянно | Паттерны, антипаттерны, ADR | База знаний |

**Операционная ошибка:** хранение project state внутри session context.

---

## 2. Ключевое различие: Session Context vs Project State

| Session Context | Project State |
|---|---|
| Временная история разговора | Решения, интерфейсы, constraints |
| Tool outputs | Task graph, прогресс |
| Промежуточные рассуждения | Verification evidence |
| **НЕ должен переживать сессию** | **ДОЛЖЕН переживать сессию** |

**Правило:** в project state промоутится только durable информация:
- утверждённые решения;
- стабильные интерфейсы;
- верифицированные findings;
- next-step checkpoints.

**НЕ промоутится:** raw chain-of-thought, шумные логи, неверифицированные догадки.

## 3. Решения для памяти

### 3.1. Mem0

**Архитектура:** vector DB + knowledge graph (dual-store).

**Лицензия:** Apache 2.0.

**Self-hosting:** полностью self-hostable.

**GitHub Stars:** ~62K (август 2026).

**Benchmark (LongMemEval):** **94.4%** — ⚠️ vendor-run (GPT-5 как reader и judge, retrieval depth 200). Независимые воспроизведения: **49.0%** (Vectorize, GPT-4o) и **73.8%** (Maximem, GPT-5). Оговорки — [08.4.1](./08.research-and-benchmarks.md); vendor-цифра не должна быть несущей для решения.

**Особенности:**
- Graph features — только в Pro tier ($249/mo).
- Free tier: 10K memories.
- Standard ($19/mo): vector-only semantic search.
- Алгоритм апреля 2026: additive extraction + мульти-сигнальная retrieval (semantic + BM25 + entity boosting); ~6.8–7.0K токенов на retrieval, p50 ~0.88–1.09s.

**Когда выбирать:** стартап / верификация, минимальный lock-in, 20 минут на старт; нужен self-host / air-gapped (Apache 2.0, SOC 2 Type I, HIPAA-ready).

### 3.2. Zep / Graphiti

**Архитектура:** temporal knowledge graph (Graphiti).

**Лицензия:** Graphiti open source; Zep CE deprecated.

**Self-hosting:** через raw Graphiti (manage Neo4j yourself).

**GitHub Stars:** ~30K (getzep/graphiti, август 2026).

**Benchmark (LongMemEval):** **90.2%** — ⚠️ vendor-run (GPT-5.4 как reader/judge); независимая оценка Vectorize: **63.8%** (GPT-4o). LoCoMo: 94.7% (vendor-run).

**Особенности:**
- First-class validity windows on all edges.
- Bi-temporal model — единственное зрелое решение для temporal reasoning.
- Retrieval latency: **104ms p50 / 162ms p95** (LongMemEval), медианный контекст ~4.4–5.8K токенов на вопрос.
- Zep Community Edition deprecated — self-host путь: raw Graphiti + своя графовая БД (Neo4j/FalkorDB/Kuzu).

**Когда выбирать:** нужен temporal reasoning (политика изменений, эволюция предпочтений, версионирование фактов) и managed-развёртывание (SOC 2 Type II, HIPAA BAA). Минус: cloud/BYOC only, нет полноценного self-host продукта.

### 3.3. Другие решения

| Инструмент | Лицензия | Особенности |
|---|---|---|
| **Letta** (ex-MemGPT) | Apache 2.0 | Memory-first framework |
| **Cognee** | Apache 2.0 | Knowledge graph + RAG |
| **Hindsight** | Open source | Remote, mental models, temporal reasoning |

## 4. ADR и база знаний

### 4.1. Architecture Decision Records (ADR)

**Формат:** markdown в `/docs/adr/`.

**Структура:**
```yaml
decision:
  id: use-session-cookie-refresh
  date: 2026-03-25
  approved_by: lead
  rationale: Avoid token refresh race in middleware chain
  affected_interfaces:
    - src/auth/contracts.ts
```

**MCP-инструменты:**
- `search_adrs`
- `get_adr`
- `create_adr`

**Преимущества:**
- 0 дополнительной инфраструктуры.
- Git history сохраняется.
- Полная телеметрия (каждый LLM-вызов — ваш).

### 4.2. База знаний паттернов и антипаттернов

**Хранение:** markdown / YAML в репозитории.

**Доступ:** через MCP-инструменты.

**Содержимое:**
- Какие подходы выбирались.
- Из чего выбирали.
- Почему выбрали именно так.
- Какие антипаттерны обнаружены.

## 5. Графовые и векторные базы для контекста проекта

### 5.1. Код-контекст (MCP)

| Инструмент | Описание |
|---|---|
| **CodeGraphContext** | MCP-сервер, индексирует код в графовую БД |
| **Graph-Codebase-MCP** | Neo4j + AST-анализ + embeddings |
| **codebase-memory-mcp** | Персистентный knowledge graph функций, классов, вызовов |

### 5.2. Aider Repo Map

**Референс-паттерн:**
1. tree-sitter парсит AST.
2. Строит граф символов.
3. Прогоняет PageRank для ранжирования важности.
4. Бинарным поиском вписывает результат в токен-бюджет.

**Результат:** агент видит архитектуру, а не текст файлов.

### 5.3. Векторные базы

| База | Особенности |
|---|---|
| **LanceDB** | Embedded, без сервера, файл рядом с проектом |
| **Qdrant** | Self-hosted, production-ready |
| **Chroma** | Простой старт |

**Для «контекст проекта на каждой машине»:** LanceDB удобнее — embedded (файл рядом с проектом), не требует отдельного процесса, синхронизируется через git или общий storage.

### 5.4. SurrealDB

**SurrealDB 3.0** (выпущен 17 февраля 2026 ): graph + vector + document + temporal + relational + time-series + geospatial + key-value в одном движке .

**Производительность (vendor-замеры февраля 2026, vs 2.x):** in-memory creates **2.7×**, updates **3.5×**, full-field scans (2000 строк) **6.5×** быстрее; индексные lookup на миллионных таблицах — от секунд до миллисекунд. Ранее заявленные «8–22× на графовых запросах» **не подтвердились** — не использовать.

**Финансирование:** $23M в новом раунде с релизом 3.0 .

**Дополнительно:** SurrealDB 3.1 (2026) добавил встроенный MCP-сервер (`surreal mcp`, 12 типизированных инструментов с `readOnlyHint`/`destructiveHint`) — релевантно для [11.4.4](./11.tool-engineering.md).

**Недостатки:** экосистема моложе Neo4j.

**Когда выбирать:** нужно единое хранилище для всех типов данных, развёртывание на каждой машине.

## 6. Механизмы работы с памятью в harness

### 6.1. Fresh-Context Workers

**Механизм:** каждый воркер спавнится с:
- bounded task brief;
- owned files и explicit `do_not_touch` boundaries;
- frozen interface contracts;
- verification commands или acceptance checks.

**Не передавать:** весь orchestrator transcript, если задача не зависит от него.

### 6.2. Durable External State

**Механизм:** project state персистится в reviewable files:
- markdown with frontmatter;
- YAML;
- JSON;
- task manifests.

**Что персистить:**
- active plan и milestones;
- dependency graph и unblock conditions;
- decisions и rationale;
- changed-path ownership;
- verification evidence и unresolved risks.

### 6.3. Session-to-Project Promotion

**Механизм:** только durable информация промоутится из session context в project state:
- approved decisions;
- stable interfaces;
- verified findings;
- next-step checkpoints.

**НЕ промоутится:** raw chain-of-thought, noisy logs, unverified guesses.

### 6.4. Когда Respawn Worker

**Предпочесть свежий worker / сессию:**
- задача меняется с exploration на implementation;
- worker пересёк значимую фазовую границу;
- контекст содержит multiple unrelated branches of reasoning;
- задача возобновляется после долгой паузы;
- worker выиграет больше от чистого brief, чем от conversational history.

---

## 7. Практические рекомендации

1. **Разделяйте session context и project state.** Не храните project state внутри session context.
2. **Начните с markdown + MCP.** Дёшево, git-friendly, полная телеметрия.
3. **Промоутьте только durable информацию.** Не весь chain-of-thought.
4. **Fresh-context workers.** Чистый brief вместо истории.
5. **Используйте ADR.** Markdown в репозитории + MCP-инструменты.
6. **Для temporal reasoning — Graphiti.** Bi-temporal model — единственное зрелое решение.
7. **Для простоты — Mem0 или markdown + MCP.**
8. **SurrealDB — если нужно единое хранилище.**
