# ideas/ — идеи и принципы с высокой ценностью

Коллекция идей, выделенных из обработанного корпуса как потенциально лежащих в основу новой системы процессов разработки с AI-агентами. Каждая идея описана единообразно: **проблема, которую она решает → почему готовые решения не закрывают её полностью → какую ценность даёт → возможная архитектура**.

## Как это устроено

Это не готовая система и не спецификация — это **зародыш**: набор связных идей с обоснованием ценности и архитектурными эскизами. Часть идей уже начата прорабатывать (архитектура базы знаний — `knowledge-architecture/`), часть — синтезированы из критики и ландшафта.

Пять кластеров, образующих единую архитектурную рамку:

| Кластер | Ядро | Ключевая ценность |
|---|---|---|
| [knowledge-architecture/](knowledge-architecture/) | Контент стабилен, структура виртуальна (notes/+views/) | KB, дешёвая для человека и агента, с чистым diff |
| [process-core/](process-core/) | Уровни масштаба × модульность × дешевая форма | Overhead процесса пропорционален риску |
| [agent-governance/](agent-governance/) | Durable context + явная приёмка + handoff | Агент управляем, контекст переносим, приёмка явна |
| [enforcement/](enforcement/) | Блокирующие машинные gate | Устойчивость через enforcement, не доверие |
| [tooling-strategy/](tooling-strategy/) | Процесс > инструмента, adopt/adapt/build | Независимость от вендоров, осознанный выбор tooling |

## Статусы идей

- **core-candidate** — претендент на ядро новой системы (knowledge-architecture, process-core).
- **differentiator** — то, чего нет у готовых решений (agent-governance: handoff, ведомость допущений; enforcement: блокирующие gate).
- **supporting** — поддерживающие решения (tooling-strategy).

## Принцип отбора

Идея попадает сюда, если: (1) решает реальную задокументированную проблему; (2) готовые решения не закрывают её полностью или закрывают с vendor-lock/компромиссом; (3) имеет проверяемую ценность; (4) может быть скомбинирована с другими идеями в связную архитектуру. Принцип фильтра (пользователь): **избегать ненужного трения** — каждая идея проверяется, не добавляет ли она friction сверх ценности.
