# Идея: управление AI-агентами — durable context, явная приёмка, переносимый handoff

| Параметр | Значение |
|---|---|
| Статус | differentiator (то, чего нет у готовых решений в связке) |
| Обновлено | 2026-09-30 |
| Происхождение | Синтез фаз 2, 5, 6 (критика SDD, AI-collab, SpecWeave) |

## Проблема

AI-агент в процессе дестабилизирует его тремя способами:

1. **Контекст теряется и переобъясняется.** Между сессиями агент «забывает всё»; durable context размазан по чатам, а не зафиксирован в читаемых агентом артефактах. При смене инструмента/аккаунта — потеря полная.
2. **Приёмка неявная.** По отсутствию замечания невозможно отличить просмотренное от непросмотренного: молчание трактуется как согласие, а не как неизвестный статус. Допущения агента (где спека молчала) оседают в коде невидимо.
3. **Агент обходит контроль.** Минимизирует «трение»: обходит проверки флагом, принимает архитектурные решения, отклоняется от спеки — потому что gate либо advisory, либо в его досягаемости.

## Почему готовые решения не закрывают

- **AGENTS.md/CLAUDE.md поодиночке** — durable context, но привязка к harness (CLAUDE.md — только Claude); нет механизма явной приёмки.
- **SDD-инструменты** — дают durable context через спеки, но: OpenSpec — advisory verification; Spec Kit — контекст не переносится между вендорами; ни один не ведёт ведомость допущений.
- **SpecWeave** — закрывает handoff и memory, но это отдельный инструмент; механизм стоит перенять как принцип, а не как зависимость.
- **HITL «в общем»** — все декларируют human-in-the-loop, но без именованных протоколов и явных статусов приёмки это молчание = согласие.

## Ценность

Связка механизмов, делающая агента управляемым, а контекст — переносимым, а приёмку — явной:

- **Durable context без vendor-lock**: canonical AGENTS.md (cross-tool стандарт) + tool-specific файлы импортируют; агент читает артефакты, а не переобъяснения.
- **Явная приёмка**: фриз фиксирует область принятого; «не заметил» и «принял» — разные статусы; **ведомость допущений** — агент перечисляет, где спека молчала и он выбирал сам; принятое поднимается в спеку («удача оставляет след так же, как ошибка»).
- **Переносимый handoff**: работа и project memory переносятся между вендорами/аккаунтами через закоммиченные артефакты, а не через привязку к harness.
- **Управление через протоколы, не доверие**: HITL как именованные паттерны; gate вне досягаемости агента.

## Архитектура

### Слой 1: Durable context

```
CONSTITUTION.md   # immutable principles, amendment через RFC, Governance-секция
AGENTS.md         # canonical cross-tool operational rules
CLAUDE.md → @AGENTS.md   # tool-specific файлы импортируют, не дублируют
src/<module>/AGENTS.md   # hierarchical loading: ближайший в дереве
```

Порядок чтения агентом: CONSTITUTION.md → AGENTS.md → specs/\<feature\>/. Правила: конкретные версии, полные флаги, < 500 строк, security prominent, обновлять при смене конвенций. Конституция — не конфиг: каждый запрет с rationale.

### Слой 2: Протоколы handoff (HITL-паттерны)

Именованные протоколы вместо «human-in-the-loop в общем»:

| Паттерн | Применение | Поток |
|---|---|---|
| **AI Drafts, Human Decides** | ADR, RFC, PRD | агент черновик → человек ревьюит → человек решает |
| **AI Generates, Human Validates** | Requirements, Tasks, API Specs | агент → автопроверки → человек валидирует |
| **AI Assists, Human Executes** | Implementation, Testing | человек описывает → агент подсказывает → человек реализует |
| **Human Defines, AI Implements** | Implementation после approval | человек спека → агент код → автотесты → человек ревьюит → merge |

### Слой 3: Явная приёмка и ведомость допущений

- **Две версии кода**: опорная (immutable, точка сравнения) + рабочая (правит агент); после разбора перехода рабочая → опорной.
- **Фриз**: фиксирует область явно принятого; остальное — непросмотренное с неизвестным статусом. **Молчание не считается согласием.**
- **Ведомость допущений**: агент отдельно перечисляет места, где спека молчала и он выбирал сам; по каждому расхождению статус: отклонить / принять без переноса / поднять в спеку / признать каноническим / отложить.
- **Сжатые представления как индексы к коду** (6 типов: проверка на закреплённом входе, инвариант, контракт границы, карта понятий, граф связей, основание решения) — быстрое понимание смысла изменения без чтения всего кода; не вторая спека.

### Слой 4: Переносимый handoff и memory

Работа и контекст переносятся через **закоммиченные артефакты**, не через harness: branch + snapshot правок + ledger (claims, причина остановки, evidence) + project memory в репо (формат MEMORY.md, но committed). «Hand off» в одном инструменте → «pick up» в любом другом (вендор, аккаунт, машина, cloud). Контекстная инженерия: мониторинг заполнения окна (порог 50–60%), delta-загрузка, разбиение больших задач.
