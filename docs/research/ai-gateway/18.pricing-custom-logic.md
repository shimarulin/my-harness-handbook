# Кастомная логика получения актуальных цен

## Проблема

Некоторые провайдеры:
- не представлены в публичных каталогах цен (например, корпоративные развёртывания, приватные модели);
- имеют разную тарификацию в зависимости от подписки (Claude Pro vs API, ChatGPT Plus vs API);
- меняют цены динамически (сезонные скидки, объёмные скидки).

Стандартный реестр цен LiteLLM/Portkey не покрывает такие случаи. Нужен механизм добавления кастомной логики получения цен.

## Подходы

### Подход 1: Кастомный callback в LiteLLM (рекомендуемый)

LiteLLM поддерживает регистрацию кастомных callback-классов, которые вызываются после каждого успешного запроса. В callback доступны:
- `response_cost` — стоимость, вычисленная LiteLLM;
- `model` — имя модели;
- `usage` — токены (prompt, completion, total);
- `metadata` — метаданные запроса.

**Схема:**

1. Написать класс-наследник `CustomLogger`.
2. Реализовать метод `log_success_event`, который:
   - получает токены из `response_obj`;
   - обращается к внешнему источнику цен (API провайдера, база данных, конфиг-файл);
   - вычисляет стоимость и записывает её в систему учёта.
3. Зарегистрировать класс в `litellm_settings.callbacks`.

**Пример:**

```python
# custom_pricing.py
import litellm
import requests

class DynamicPricingLogger(litellm.integrations.custom_logger.CustomLogger):
    def __init__(self):
        self.pricing_cache = {}

    def log_success_event(self, kwargs, response_obj, start_time, end_time):
        model = kwargs.get("model")
        usage = response_obj.get("usage", {})
        prompt_tokens = usage.get("prompt_tokens", 0)
        completion_tokens = usage.get("completion_tokens", 0)

        pricing = self.fetch_pricing(model)
        input_cost = prompt_tokens * pricing["input"]
        output_cost = completion_tokens * pricing["output"]
        total_cost = input_cost + output_cost

        # Записать в систему учёта (лог, БД, webhook)
        self.record_cost(model, total_cost, kwargs)

    def fetch_pricing(self, model):
        # Кэширование на 5 минут
        if model in self.pricing_cache:
            return self.pricing_cache[model]

        # Пример: запрос к API провайдера
        # response = requests.get(f"https://provider.com/api/pricing?model={model}")
        # pricing = response.json()

        # Или чтение из локальной таблицы
        pricing = {
            "openai/gpt-4o": {"input": 0.000005, "output": 0.000015},
            "anthropic/claude-sonnet-4-20250514": {"input": 0.000003, "output": 0.000015},
            "custom/private-model": {"input": 0.000001, "output": 0.000002},
        }.get(model, {"input": 0.000001, "output": 0.000002})

        self.pricing_cache[model] = pricing
        return pricing

    def record_cost(self, model, cost, kwargs):
        # Запись в БД, отправка в webhook, логирование
        print(f"[PRICING] {model}: ${cost:.6f}")
        # Например, сохранить в SQLite или отправить в Prometheus
```

Регистрация в `config.yaml`:

```yaml
litellm_settings:
  callbacks: custom_pricing.DynamicPricingLogger
```

### Подход 2: Custom pricing для конкретных моделей

Если цена фиксированная, но отличается от публичной, можно использовать `custom_pricing` в конфиге LiteLLM:

```yaml
model_list:
  - model_name: "private-model"
    litellm_params:
      model: "openai/private-model"
      api_base: "https://internal-llm.company.com/v1"
      api_key: "os.environ/INTERNAL_API_KEY"
    model_info:
      input_cost_per_token: 0.000001
      output_cost_per_token: 0.000002
```

### Подход 3: Внешний сервис цен

Можно вынести логику получения цен в отдельный микросервис, который:
- периодически опрашивает API провайдеров;
- хранит актуальные цены в БД;
- предоставляет эндпойнт для LiteLLM callback.

Этот подход оправдан, если цен много и они часто меняются.

### Подход 4: Сортировка моделей по цене

Для сортировки однотипных моделей по ценам можно:
1. Собирать цены в кастомный callback.
2. Предоставлять их через отдельный эндпойнт (например, `/custom/pricing`).
3. На стороне клиента (или в кастомном middleware) сортировать модели по цене перед отправкой запроса.

Пример middleware для LiteLLM:

```python
# Добавить кастомный эндпойнт через FastAPI (LiteLLM proxy built on FastAPI)
from litellm.proxy.proxy_server import app

@app.get("/custom/pricing")
async def get_pricing():
    # Вернуть актуальные цены, отсортированные по возрастанию
    return {
        "models": [
            {"name": "gpt-4o-mini", "input": 0.00000015, "output": 0.0000006},
            {"name": "gpt-4o", "input": 0.000005, "output": 0.000015},
        ]
    }
```
