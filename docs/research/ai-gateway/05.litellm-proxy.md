# LiteLLM Proxy: настройка и использование

## Что это

LiteLLM — open-source Python SDK и прокси-сервер, который предоставляет единый OpenAI-совместимый API для 100+ LLM-провайдеров. Ядро под лицензией MIT, self-hosted. Может работать как SDK (встраивание в код) или как отдельный прокси-сервер (именно этот режим нужен для агрегации).

**Ключевые возможности:**
- Единый эндпойнт `/v1/chat/completions` для OpenAI, Anthropic, Gemini, Bedrock, Azure, Groq, Ollama, vLLM и др.
- Маршрутизация по имени модели с префиксами провайдеров (`openai/gpt-4o`, `anthropic/claude-sonnet-4-20250514`, `gemini/gemini-2.5-pro`).
- Fallback: цепочки моделей при ошибках (429, 5xx, timeout, ContentPolicyViolationError).
- Load balancing: распределение запросов между несколькими деплоями одной модели по весам.
- Spend tracking: автоматический учёт расходов по ключам, пользователям, командам.
- Custom pricing: переопределение цен для моделей, отсутствующих в реестре.
- Virtual keys: управление доступом и бюджетами.
- Callbacks: интеграция с внешними системами (Langfuse, Lago, кастомные логгеры).

## Быстрый старт

### Установка

```bash
pip install 'litellm[proxy]'
```

### Минимальный конфиг `config.yaml`

```yaml
model_list:
  - model_name: "gpt-4o"
    litellm_params:
      model: "openai/gpt-4o"
      api_key: "os.environ/OPENAI_API_KEY"

  - model_name: "claude-sonnet"
    litellm_params:
      model: "anthropic/claude-sonnet-4-20250514"
      api_key: "os.environ/ANTHROPIC_API_KEY"

  - model_name: "llama3"
    litellm_params:
      model: "ollama/llama3"
      api_base: "http://localhost:11434"

general_settings:
  master_key: "sk-litellm-master-key"
```

### Запуск

```bash
litellm --config /path/to/config.yaml --port 4000
```

Прокси будет доступен по адресу `http://localhost:4000/v1`.

### Использование с любым OpenAI-совместимым клиентом

```python
from openai import OpenAI

client = OpenAI(
    api_key="sk-litellm-master-key",
    base_url="http://localhost:4000/v1"
)

response = client.chat.completions.create(
    model="gpt-4o",  # LiteLLM маршрутизирует в OpenAI
    messages=[{"role": "user", "content": "Hello!"}]
)
```

## Fallback (перенаправление при ошибке)

Fallback настраивается на двух уровнях: в `litellm_params` (конкретный деплой) и в `litellm_settings` (глобальные цепочки).

### Цепочки fallback

```yaml
model_list:
  - model_name: "primary-model"
    litellm_params:
      model: "openai/gpt-4o"
      api_key: "os.environ/OPENAI_API_KEY"

  - model_name: "fallback-model"
    litellm_params:
      model: "anthropic/claude-sonnet-4-20250514"
      api_key: "os.environ/ANTHROPIC_API_KEY"

  - model_name: "fallback-model-2"
    litellm_params:
      model: "gemini/gemini-2.5-pro"
      api_key: "os.environ/GEMINI_API_KEY"

litellm_settings:
  num_retries: 2
  request_timeout: 120
  fallbacks:
    - primary-model: ["fallback-model", "fallback-model-2"]
```

При ошибке `primary-model` LiteLLM последовательно пробует `fallback-model`, затем `fallback-model-2`. Важно: fallback-цели должны быть `model_name`-алиасами, а не строками провайдеров.

### Типы fallback

| Ключ | Когда срабатывает |
|---|---|
| `fallbacks` | Общие ошибки (5xx, timeout) |
| `context_window_fallbacks` | `ContextWindowExceededError` |
| `content_policy_fallbacks` | `ContentPolicyViolationError` |
| `default_fallbacks` | Catch-all для всех остальных случаев |

## Кастомные цены

LiteLLM автоматически отслеживает расходы для известных моделей. Если провайдер отсутствует в публичном реестре или имеет другую тарификацию (например, в зависимости от подписки), цену можно переопределить.

### Способ 1: Custom pricing через callback

LiteLLM предоставляет механизм `custom_pricing`, который позволяет указать стоимость input/output токенов для любой модели. Это работает для приватных и self-hosted моделей.

### Способ 2: Custom callback для получения актуальных цен

Если цены меняются динамически (например, зависят от подписки или текущего тарифа провайдера), можно написать собственный callback, который будет вычислять стоимость после каждого запроса.

LiteLLM поддерживает следующие callback-события:
- `log_pre_api_call`
- `log_post_api_call`
- `log_success_event` (содержит `response_cost` в kwargs)
- `log_failure_event`

Кастомный логгер регистрируется в `litellm_settings.callbacks`.

### Пример: callback для кастомного расчёта цены

```python
# custom_pricing_callback.py
import litellm

class CustomPricingLogger(litellm.integrations.custom_logger.CustomLogger):
    def log_success_event(self, kwargs, response_obj, start_time, end_time):
        model = kwargs.get("model")
        usage = response_obj.get("usage", {})
        prompt_tokens = usage.get("prompt_tokens", 0)
        completion_tokens = usage.get("completion_tokens", 0)

        # Кастомная логика: получить актуальную цену из внешнего источника
        input_cost, output_cost = self.get_pricing(model)

        total_cost = (prompt_tokens * input_cost) + (completion_tokens * output_cost)
        # Записать стоимость в систему учёта
        print(f"Custom cost for {model}: ${total_cost}")

    def get_pricing(self, model):
        # Здесь может быть запрос к API провайдера, чтение из БД
        # или любая другая логика получения актуальных цен
        pricing_table = {
            "openai/gpt-4o": (0.000005, 0.000015),  # $/token
            "anthropic/claude-sonnet-4-20250514": (0.000003, 0.000015),
        }
        return pricing_table.get(model, (0.000001, 0.000002))
```

Регистрация в конфиге:

```yaml
litellm_settings:
  callbacks: custom_pricing_callback.CustomPricingLogger
```

### Способ 3: Внешние системы биллинга

LiteLLM поддерживает интеграцию с Lago для биллинга. Достаточно установить `lago` в качестве callback:

```yaml
litellm_settings:
  callbacks: ["lago"]
```

Подробнее: [LiteLLM Billing docs](https://docs.litellm.ai/docs/proxy/billing).

## Load balancing между деплоями одной модели

Если у вас несколько API-ключей или провайдеров для одной и той же модели, можно настроить балансировку:

```yaml
model_list:
  - model_name: "balanced-group"
    litellm_params:
      model: "groq/llama-3.1-8b-instant"
      api_key: "os.environ/GROQ_API_KEY"
      weight: 1
  - model_name: "balanced-group"
    litellm_params:
      model: "bedrock/us.amazon.nova-micro-v1:0"
      aws_region_name: "us-west-2"
      weight: 1

router_settings:
  routing_strategy: "simple-shuffle"  # или least-busy, usage-based-routing, latency-based-routing, cost-based-routing
```

Стратегии маршрутизации:
- `simple-shuffle` — случайное распределение (по умолчанию);
- `least-busy` — наименьшее количество активных запросов;
- `usage-based-routing` — наименьший RPM/TPM;
- `latency-based-routing` — самый быстрый отклик;
- `cost-based-routing` — самая дешёвая модель.

## Сортировка моделей по цене

LiteLLM не предоставляет встроенного эндпойнта для сортировки моделей по цене, но это можно реализовать через:

1. **Кастомный callback**, который собирает данные о ценах и предоставляет их через отдельный API.
2. **Внешний сервис**, который читает `model_list` из конфига LiteLLM и ценовой реестр, затем сортирует.
3. **Использование `cost-based-routing`** — LiteLLM сам выбирает самую дешёвую модель из группы.

Пример сортировки на стороне клиента (после получения списка моделей через `/v1/models`):

```python
import requests

models = requests.get("http://localhost:4000/v1/models").json()["data"]
# Цены можно получить из кастомного эндпойнта или из локальной таблицы
priced_models = [(m["id"], get_price(m["id"])) for m in models]
sorted_models = sorted(priced_models, key=lambda x: x[1])
```

## Полезные эндпойнты

| Эндпойнт | Метод | Назначение |
|---|---|---|
| `/v1/chat/completions` | POST | Чат-комплишены (OpenAI-совместимые) |
| `/v1/models` | GET | Список доступных моделей |
| `/key/generate` | POST | Создать virtual key |
| `/key/info` | GET | Информация о ключе и расходах |
| `/spend/logs` | GET | Логи расходов |
| `/health` | GET | Проверка работоспособности |
