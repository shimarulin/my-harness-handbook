# Проблема Model Discovery для кастомных провайдеров в LiteLLM

## Суть

LiteLLM Model Discovery не работает для **кастомных OpenAI-совместимых провайдеров** (тип `custom_openai`). Это открытый feature request [#20064](https://github.com/BerriAI/litellm/issues/20064).

## Детали

При вызове `/v1/models` LiteLLM не триггерит discovery-запрос к кастомному провайдеру. Ожидаемое поведение:

> a call to the LiteLLM proxy's `/v1/models` endpoint should trigger a discovery call to `http://my-custom-provider-url.com/v1/models` and return the result in the expected format.

## Поддерживаемые провайдеры для Model Discovery

Официально поддерживаются:
- Fireworks AI
- OpenAI
- Gemini
- LiteLLM Proxy (вложенный)
- Topaz
- Anthropic
- XAI
- VLLM
- Vertex AI
- Eden AI

Кастомные OpenAI-совместимые провайдеры **не входят** в этот список.

## Альтернативы

Для кастомных провайдеров используйте лёгкие шлюзы, поддерживающие Model Discovery:
- `femtollm` — discovery-based routing без указания имён моделей в конфиге;
- `ldrouter` — selective model discovery (Fetch → select → import);
- `llmproxy` — multi-model discovery (union всех провайдеров);
- `Manifest LLM Gateway` — discovery через `/v1/models`.
