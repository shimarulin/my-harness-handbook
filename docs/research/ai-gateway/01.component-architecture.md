# Компонентная архитектура: шесть независимых задач

## Обзор

Задача «подключить харнессы к агрегированному шлюзу с полными метаданными» разбивается на шесть независимых компонентов. Каждый решается отдельным инструментом.

## Компонент 1: Auto-discovery моделей

**Задача:** получить список моделей от провайдеров, записать в конфиг или БД.

| Инструмент | Формат | Особенности |
|---|---|---|
| `kosha-discovery` | Library / CLI / HTTP API | 25+ провайдеров, enrichment из LiteLLM dataset |
| `llm-discovery` | JSON, CSV, YAML, Markdown, TOML | Prebuilt data без ключей (max 24h old) |
| `llm-aggregator` | Web UI + REST API | Multi-provider discovery + AI-enrichment |
| `starmap` | Go package / CLI / HTTP | 500+ моделей, 10+ провайдеров |
| `modelpedia` | npm library | 4000+ моделей, 30+ провайдеров |
| `openmodels` | YAML registry | 151 модель, 52 провайдера, 224 mapping'а |

**Ограничение:** `/v1/models` отдаёт только `id` и `object`. Discovery даёт список, но не метаданные.

## Компонент 2: Обогащение данных

**Задача:** получить актуальные цены, contextWindow, maxTokens, capabilities.

| Инструмент | Что даёт | Особенности |
|---|---|---|
| `llmux` | Per-request cost из live auto-synced каталога | Precedence: override > provider API > LiteLLM > OpenRouter > built-in seed; route-aware |
| `claudescope` | Pricing для Claude Code, Codex, opencode | Auto-refresh из LiteLLM; provider override для zero-rating local |
| `@pydantic/genai-prices` | Расчёт цены по usage | Custom pricing objects |
| `@reaatech/otel-cost-exporter-pricing` | Bundled data + custom YAML | Merge custom overrides |
| `openai-cost-calculator` | USD cost across 13 providers | Prices from official pricing API |
| `LLM Pricing Scraper` (Apify) | 400+ моделей, price comparison | Programmatic access |
| `crawl4ai` | Парсинг страниц кастомных провайдеров | LLMExtractionStrategy |

## Компонент 3: Поддержка any OpenAI-compatible service

**Задача:** шлюз должен принимать любой OpenAI-совместимый endpoint.

| Шлюз | Кастомные OpenAI | Установка | Лёгкость |
|---|---|---|---|
| **Aurora OSS** | 14 provider types | Docker / npm | Go, single binary, 55x faster than LiteLLM |
| **Ferro Labs** | BASE_URL override | One-line / Homebrew / binary | Go, single binary |
| **LiteLLM** | custom_openai (discovery не работает) | Docker / pip | Python, тяжёлый |
| **llmproxy** | Any OpenAI-compatible | Flask / Docker | Python, лёгкий |
| **Leyline** | Gemini, HuggingFace, OpenRouter, Ollama, custom | npm | лёгкий |
| **Manifest** | «any custom endpoint» | Docker | средний |

## Компонент 4: Роутинг и fallback

**Задача:** перенаправление при ошибке или высоком пинге.

Решается тем же шлюзом, что и компонент 3:

- **Aurora OSS:** automatic failover on 5xx/429, manual rules.
- **Ferro Labs:** Fallback (exponential backoff), Weighted LB, Conditional, A/B test.
- **LiteLLM:** `fallbacks`, `context_window_fallbacks`, `content_policy_fallbacks`, `default_fallbacks`.

## Компонент 5: Передача данных в харнесс (Pi)

**Задача:** обогатить ответ шлюза или сгенерировать `models.json` с полными полями.

| Подход | Инструмент | Как работает |
|---|---|---|
| Pi-расширение | `pi-openai-api-models-sync` | `/models` + Sub2API enrichment + `pi.registerProvider()` |
| Pi-расширение | `@brglng/pi-model-discovery` | `<baseUrl>/models` + per-model overrides |
| Pi-расширение | `better-custom-provider` | models.dev + несколько источников |
| Sidecar-прокси | `llmux` | `GET /v1/models` с pricing + capabilities; `GET /v1/catalog.json` |
| CLI | `llm-discovery export` | `--format json --output models.json` |

## Компонент 6: Отслеживание стоимости и токенов

**Задача:** учёт расходов и потребления.

| Инструмент | Что даёт | Особенности |
|---|---|---|
| `inferrail` | Cost attribution by customer/workflow/task | Без хранения промптов; verified pricing |
| `tracetokens` | Token consumption, micro-dollar costs, TTFT | 1-line SDK + Universal AI Gateway Proxy |
| `@bryxen/pulse` | Per-model input/output/cache pricing | Single Bun process |
| `OngoingAI Gateway` | Tracing, cost visibility, audit-ready logs | Works with OpenAI, Anthropic, compatible |
| `LLM Gateway` | Analytics by model/key/member | Cost/token/request breakdowns |
| `any-llm-gateway` | Budgeting, analytics, access management | OpenAI-compatible |
| `Portkey` | Real-time cost tracking, per-user attribution | Enterprise-grade |

## Итоговая архитектура

```
Auto-discovery (kosha-discovery / llm-discovery)
    ↓
Обогащение (llmux / claudescope / genai-prices)
    ↓
Шлюз (Aurora OSS / Ferro Labs / LiteLLM)
    • any OpenAI-compatible
    • роутинг + fallback
    • cost tracking
    ↓
Передача в Pi (pi-openai-api-models-sync / sidecar)
```

**Минимальная конфигурация:** Aurora OSS + `pi-openai-api-models-sync`.

**Максимальная гибкость:** Ferro Labs + kosha-discovery + llmux + sidecar.
