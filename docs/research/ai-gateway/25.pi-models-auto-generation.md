# Автоматическая генерация `models.json` для Pi Coding Agent

## Проблема

Pi Coding Agent не запрашивает `/v1/models` автоматически — он знает только те модели, которые прописаны вручную в `~/.pi/agent/models.json`. Для шлюзов с десятками моделей (LiteLLM, Portkey) ручное заполнение `contextWindow`, `maxTokens`, `cost` и `reasoning` непрактично.

**Ключевое ограничение:** `/v1/models` в большинстве шлюзов отдаёт только `id` и `object`. Поля `contextWindow`, `maxTokens`, `cost`, `reasoning` **не входят** в стандартный ответ OpenAI-совместимого эндпойнта. Расширения решают это двумя путями:
1. Используют **дополнительные эндпойнты** шлюза с метаданными (LiteLLM `/model/info`, `/model_group/info`).
2. **Обогащают** список из `/v1/models` данными из внешнего каталога цен.

## Расширения общего назначения

### `pi-openai-api-models-sync` (riverscn)

Синхронизирует модели из `/v1/models` и обогащает их метаданными из внешнего каталога (по умолчанию Sub2API metadata repository).

**Установка:**
```bash
pi install npm:pi-openai-api-models-sync
```

**Как работает:**
1. Находит все `openai-responses` и `openai-completions` провайдеры в `models.json`.
2. Запрашивает `<baseUrl>/models` с аутентификацией провайдера.
3. Подтягивает метаданные о ценах и возможностях.
4. Пересекает доступные ID моделей с метаданными.
5. Регистрирует модели через `pi.registerProvider()`.

**Настройка:**
```json
{
  "providers": {
    "openai-api": {
      "baseUrl": "https://api.example.com/v1",
      "api": "openai-responses",
      "apiKey": "$OPENAI_API_KEY",
      "authHeader": true,
      "models": [
        { "id": "placeholder" }
      ]
    }
  }
}
```

Статическая запись `models` — только bootstrap и fallback. После успешной синхронизации расширение заменяет её для активного процесса Pi.

**Опции конфигурации:**
- `providerId` — синхронизировать только одного провайдера;
- `pricingUrl` — URL своего источника метаданных (вместо Sub2API);
- `include` / `exclude` — регулярки для фильтрации моделей.

**Ссылки:**
- [pi-openai-api-models-sync — GitHub](https://github.com/riverscn/pi-openai-api-models-sync)

### `pi-model-discovery` (brglng)

Универсальное расширение, использующее только секцию `providers` в `models.json`. Запрашивает `<baseUrl>/models` и принимает OpenAI-стиль (`data`), голые массивы, каталоги, вложенные в `models` или `output.models`.

**Установка:**
```bash
pi install npm:@brglng/pi-model-discovery
```

**Конфигурация:**
```json
{
  "providers": {
    "gateway": {
      "$schema": "https://raw.githubusercontent.com/brglng/pi-model-discovery/main/schemas/config.schema.json",
      "name": "My Gateway",
      "baseUrl": "https://api.example.com/v1",
      "apiKey": "$GATEWAY_API_KEY",
      "api": "openai-completions",
      "models": [
        {
          "id": "special-model",
          "api": "openai-responses",
          "baseUrl": "http://192.168.5.46:18000/v1",
          "maxTokens": 32768
        }
      ]
    }
  }
}
```

**Команды:**
- `/model-discovery status` — показывает провайдеров и количество моделей;
- `/model-discovery refresh` — обновляет все каталоги;
- `/model-discovery refresh <provider>` — обновляет один каталог.

**Ограничение:** если сервер не возвращает `contextWindow`, `maxTokens`, `cost` в `/v1/models`, расширение не сгенерирует их автоматически — потребуются ручные overrides.

**Ссылки:**
- [pi-model-discovery — GitHub](https://github.com/brglng/pi-model-discovery)
- [pi-model-discovery — npm](https://www.npmjs.com/package/@brglng/pi-model-discovery)

### `@haukuen/auto-models`

Автоматически обнаруживает и регистрирует модели OpenAI-совместимых провайдеров, избавляя от ручного прописывания `contextWindow`, `maxTokens`, `reasoning` и цен.

**Установка:**
```bash
pi install npm:@haukuen/auto-models@0.1.0
```

**Ссылки:**
- [@haukuen/auto-models — npm](https://www.npmjs.com/package/@haukuen/auto-models)

### `pi-diy-provider`

Расширение для настройки кастомных провайдеров без редактирования JSON. Записывает определения в `models.json`, обновляет реестр и перезагружает runtime.

**Установка:**
```bash
pi install npm:pi-diy-provider
```

**Команды:**
- `/provider-add` — интерактивная настройка (ID, имя, Base URL, API type, discovery/manual);
- `/login <provider-id>` — вход;
- `/provider-model-sync <provider-id>` — синхронизация каталога моделей.

**Discovery:** распознаёт OpenAI- и Anthropic-стиль (`{"data": [...]}`), а также Google-стиль (`{"models": [...]}`). Таймаут — 20 секунд. Если релей не предоставляет `/v1/models`, потребуется ручной ввод моделей.

**Безопасность:** API-ключ не записывается в `models.json`; перед изменением создаётся timestamped backup.

**Ссылки:**
- [pi-diy-provider — Socket.dev](https://socket.dev/npm/package/pi-diy-provider/overview/0.1.1)
- [pi-diy-provider — GitHub](https://github.com/chen-985211/pi-diy-provider)

## Расширения для конкретных шлюзов

### `pi-provider-litellm` (рекомендуемый для LiteLLM)

Нативное расширение для LiteLLM Proxy. **Наиболее релевантный вариант**, поскольку LiteLLM предоставляет богатые метаданные о моделях через `/model/info`.

**Установка:**
```bash
pi install npm:pi-provider-litellm
```

**Discovery-логика:**
1. `/model/info` — admin-эндпойнт с богатыми метаданными (context_window, max_input_tokens, max_output_tokens, input_cost_per_token, output_cost_per_token).
2. При 401/403/404 — откат к `/v1/models` (OpenAI-совместимый).
3. Для старых LiteLLM — `/health` + per-endpoint `/model/info`.

**Настройка:**
```bash
# Внутри Pi:
/login litellm
# Выбрать "Sign in with an API key"
# Ввести base URL (например, http://localhost:4000)
# Ввести API-ключ
```

Или через `~/.pi/agent/auth.json`.

**Возможности:**
- `/login litellm` — интерактивный вход;
- LiteLLM MCP tools;
- LiteLLM Skills Gateway prompt injection;
- Google ADC token auth;
- Enterprise SSO/OAuth.

**Требования:** Pi 0.81.0+.

**Ссылки:**
- [pi-provider-litellm — pi.dev](https://pi.dev/packages/pi-provider-litellm)
- [pi-provider-litellm — GitHub](https://github.com/balcsida/pi-provider-litellm)
- [pi-provider-litellm — npm](https://www.npmjs.com/package/pi-provider-litellm)

### Portkey + Pi

Portkey предоставляет официальную инструкцию по интеграции с Pi через `models.json`.

**Конфигурация:**
```json
{
  "providers": {
    "portkey": {
      "api": "openai-completions",
      "baseUrl": "https://api.portkey.ai/v1",
      "apiKey": "YOUR_PORTKEY_API_KEY",
      "models": [
        {
          "id": "@openai-prod/gpt-4o",
          "name": "GPT-4o via Portkey"
        },
        {
          "id": "@anthropic-prod/claude-sonnet-4-20250514",
          "name": "Claude Sonnet 4"
        }
      ]
    }
  }
}
```

**Формат `id`:** `@<provider-slug>/<model-name>`.

**Примечание:** Portkey не предоставляет автоматического discovery-расширения для Pi. Модели нужно прописывать вручную. Однако Portkey даёт observability, cost tracking и доступ к 200+ LLM.

**Ссылки:**
- [Portkey — Pi Agent Integration](https://portkey.ai/docs/integrations/libraries/pi-agent)
- [Portkey — Coding Agents](https://portkey.ai/docs/integrations/coding-agents)

### `pi-tarmis-provider` (пример полной авто-синхронизации)

Пример расширения, которое **генерирует `models.json` напрямую** из `/v1/models` провайдера Tarmis. Эндпойнт Tarmis возвращает per-model pricing, context windows, max output, modalities и supported features — всё, что нужно для полного `models.json`.

**Ссылки:**
- [pi-tarmis-provider — GitHub](https://github.com/monotykamary/pi-tarmis-provider)
