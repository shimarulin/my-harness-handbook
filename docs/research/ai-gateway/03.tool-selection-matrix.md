# Матрица выбора инструмента: агрегация LLM с auto-discovery и метаданными для Pi

## Критерии выбора

1. **Auto-discovery моделей** — шлюз сам запрашивает список моделей у провайдера, без ручного перечисления.
2. **Кастомные OpenAI-совместимые сервисы** — поддержка любого endpoint, а не только предустановленных провайдеров.
3. **Fallback при ошибке** — автоматическое перенаправление на другую модель/провайдера при сбое.
4. **Полные метаданные** — цены (input/output/cache), contextWindow, maxTokens, reasoning — для проброса в Pi.

## Рекомендация

### Основной: Manifest LLM Gateway

- Provider catalogs discovered dynamically when credentials are connected
- Connect API keys, subscriptions you already pay for, local models, or any custom endpoint
- Send `auto` and your routing rules pick the model, with fallbacks when one fails
- Up to 5 fallback models per tier
- `GET /v1/models?cost=true` returns model input and output costs in USD per million tokens

**Ограничение:** Docker/self-hosted, не single-binary.

### Дополнение: kosha-discovery

- Fills in costs and context windows from LiteLLM's community-maintained dataset
- HTTP API: `kosha serve --port 3000`
- Может использоваться как слой обогащения для `models.json`

### Альтернатива: llmproxy (lordraw77)

- Lightweight Flask server, emulates OpenAI `/v1` API
- Multi-model discovery, automatic failover
- NVIDIA and any other OpenAI-compatible endpoint (OpenAI, Mistral, vLLM, Groq, OpenRouter, LM Studio, local Ollama/llama.cpp), Azure OpenAI, Anthropic, Google Gemini

**Ограничение:** метаданные в `/v1/models` могут быть неполными.

### Написание собственного расширения

По аналогии с `pi-provider-litellm`, которое использует `/model/info` LiteLLM для получения полных метаданных, можно написать расширение для Manifest, запрашивающее `/v1/models?cost=true` и обогащающее результат через `kosha-discovery`.
