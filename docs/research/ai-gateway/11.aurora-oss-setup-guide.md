# Aurora OSS: настройка для Pi Coding Agent

## Что это

Aurora OSS — open-source OpenAI-совместимый AI-шлюз, написанный на Go. Позиционируется как **55x faster than LiteLLM**. Поддерживает auto-discovery, provider pools, semantic caching, guardrails, audit logging — всё в одном binary под Apache 2.0.

**Ключевые возможности:**
- Auto-discovery: set any provider's `_API_KEY` as env var, restart — provider and its models appear automatically.
- Provider pools: load balancing между API-ключами (round-robin, least-loaded, weighted).
- Fallback: automatic failover on 5xx/429 responses, or manual rules.
- Cost tracking, guardrails, semantic caching.
- 14 provider types, включая vLLM и кастомные.
- OpenAI-compatible API.

## Быстрый старт

### Docker

```bash
docker run -d -p 8080:8080 \
  --name aurora \
  -e GROQ_API_KEY=gsk_your_key_here \
  -e AURORA_MASTER_KEY=your-admin-key \
  aurorahq/aurora:1.0.30
```

### npm (single binary)

```bash
npm install -g iaurora
iaurora
```

### Проверка

```bash
# Health check
curl http://localhost:8080/health

# Список моделей
curl http://localhost:8080/v1/models

# Чат-комплишен
curl http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"groq/llama-3.3-70b-versatile","messages":[{"role":"user","content":"Hello!"}]}'
```

## Auto-discovery

Aurora обнаруживает провайдеров через переменные окружения. Set any provider's `_API_KEY` and restart:

```bash
export OPENAI_API_KEY=sk-...
export ANTHROPIC_API_KEY=sk-ant-...
export GROQ_API_KEY=gsk_...
docker restart aurora
```

После рестарта все модели этих провайдеров появятся в `/v1/models` автоматически.

## Fallback-настройка

Через dashboard:
1. Откройте веб-интерфейс Aurora.
2. Перейдите в раздел provider pools / fallback rules.
3. Настройте маппинг failed provider+model → backups.
4. Или используйте автоматический failover на 5xx/429.

## Получение метаданных для Pi

Aurora отдаёт cost tracking и provider pools. Для проброса в Pi:

1. Запросите `/v1/models`.
2. Обогатите contextWindow/maxTokens через `kosha-discovery` или `RouteHub`.
3. Запишите результат в `~/.pi/agent/models.json`.
