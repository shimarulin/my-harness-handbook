# Model Discovery в LiteLLM: автоматическое получение списка моделей от провайдера

## Что это

Функция **Model Discovery** в LiteLLM позволяет при вызове `/v1/models` динамически запрашивать список моделей **у самого провайдера**, если в конфиге используется wildcard-модель. Это не отдельный фоновый синхронизатор, а механизм «на лету»: список запрашивается при каждом обращении к эндпойнту.

**Официальная документация:** [Model Discovery | liteLLM](https://docs.litellm.ai/docs/proxy/model_discovery)

## Как активировать

```yaml
model_list:
  - model_name: xai/*          # wildcard — ключевой момент
    litellm_params:
      model: xai/*             # wildcard и здесь
      api_key: os.environ/XAI_API_KEY

litellm_settings:
  check_provider_endpoint: true   # включает discovery
```

После этого `GET /v1/models` вернёт актуальный список моделей от провайдера в формате OpenAI. 

## Поддерживаемые провайдеры

Официально поддерживаются:
- Fireworks AI
- OpenAI
- Gemini
- LiteLLM Proxy (вложенный)
- Topaz
- Anthropic
- XAI
- VLLM
- Vertex AI
- Eden AI



## Ограничение: кастомные провайдеры

Для **кастомных** OpenAI-совместимых провайдеров (тип `custom_openai`) Model Discovery **не работает**. Это открытый feature request [#20064](https://github.com/BerriAI/litellm/issues/20064). Для таких провайдеров модели нужно перечислять вручную. 

## Актуализация списка

LiteLLM **не хранит** список моделей в базе — он запрашивает его при каждом вызове `/v1/models` (с учётом wildcard). Отдельного фонового процесса для Model Discovery нет.

Смежный механизм — **cost map reload**: LiteLLM периодически (каждые 10 секунд) перезагружает карту цен моделей, но это касается только цен, а не списка доступных моделей у провайдера. 

## Скрытие моделей из `/v1/models`

Можно скрыть отдельные модели из листинга, оставив их вызываемыми:

```yaml
model_list:
  - model_name: claude-sonnet-5
    litellm_params:
      model: anthropic/claude-sonnet-5
      api_key: os.environ/ANTHROPIC_API_KEY

  - model_name: text-embedding-3-small
    litellm_params:
      model: openai/text-embedding-3-small
      api_key: os.environ/OPENAI_API_KEY
    model_info:
      mode: embedding
      discoverable: false   # отсутствует в /v1/models, но вызываема
```



## Как это стыкуется с Pi

Расширение **`pi-provider-litellm`** использует эндпойнт **`/model/info`** (admin-эндпойнт LiteLLM), который возвращает богатые метаданные (context_window, max_input_tokens, max_output_tokens, input_cost_per_token, output_cost_per_token). 

**Проблема:** `/model/info` возвращает только те модели, которые **явно прописаны** в `model_list`. Wildcard-модели могут не отобразиться с полными метаданными.

**Практический вывод:** для Pi-расширения лучше явно перечислять модели в `model_list`. Model Discovery через wildcard полезен для `/v1/models`, но Pi-расширение его может не подхватить.
