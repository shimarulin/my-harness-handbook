# Manifest LLM Gateway: настройка для Pi Coding Agent

## Что это

Manifest LLM Gateway — open-source LLM router, который соединяет модели и подписки за единым OpenAI- и Anthropic-совместимым эндпойнтом. Поддерживает routing, fallbacks, limits и Autofix.

**Ключевые возможности:**
- Connect API keys, subscriptions you already pay for, local models, or any custom endpoint
- Send `auto` and your routing rules pick the model, with fallbacks when one fails
- Provider catalogs are discovered dynamically when credentials are connected
- `GET /v1/models?cost=true` returns model input and output costs in USD per million tokens
- Up to 5 fallback models per tier
- Self-hosted: Docker on your own machine, a managed platform like Railway, your AWS or GCP account

## Быстрый старт

### Docker

```bash
docker run -d --name manifest \
  -p 2099:2099 \
  manifestdotbuild/manifest:latest
```

Инстанс запустится пустым. Первый запрос — через `http://localhost:2099/v1`.

### Подключение провайдера

1. Откройте веб-интерфейс Manifest (по умолчанию на порту 2099).
2. Создайте harness.
3. Подключите провайдера: API-ключ, подписку или кастомный endpoint.
4. Назначьте default tier модель для роутинга.
5. Скопируйте gateway address и harness key (начинается с `mnfst_`).

### Проверка

```bash
curl -X POST http://localhost:2099/v1/chat/completions \
  -H "Authorization: Bearer mnfst_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "auto", "messages": [{"role": "user", "content": "Hello"}]}'
```

## Получение списка моделей с ценами

```bash
curl http://localhost:2099/v1/models?cost=true \
  -H "Authorization: Bearer mnfst_YOUR_KEY"
```

Ответ будет содержать input/output costs в USD per million tokens.

## Fallback-настройка

В dashboard:
1. Выберите tier (например, `default`).
2. Назначьте primary model.
3. Добавьте до 5 fallback-моделей.
4. Routing rules будут применять fallback при ошибке primary.

## Генерация `models.json` для Pi

Manifest не предоставляет готового расширения для Pi, но можно:

1. **Вручную** заполнить `models.json`, используя данные из `/v1/models?cost=true`.
2. **Написать скрипт**, который:
   - запрашивает `/v1/models?cost=true`;
   - преобразует ответ в формат `models.json`;
   - обогащает `contextWindow` и `maxTokens` из `kosha-discovery` (если Manifest их не отдаёт);
   - записывает результат в `~/.pi/agent/models.json`.

Пример скрипта:

```python
import requests
import json
import os

MANIFEST_URL = "http://localhost:2099"
MANIFEST_KEY = os.environ["MANIFEST_KEY"]

resp = requests.get(
    f"{MANIFEST_URL}/v1/models?cost=true",
    headers={"Authorization": f"Bearer {MANIFEST_KEY}"}
)
models = resp.json()["data"]

providers = {
    "manifest": {
        "baseUrl": f"{MANIFEST_URL}/v1",
        "api": "openai-completions",
        "apiKey": "$MANIFEST_KEY",
        "models": []
    }
}

for m in models:
    providers["manifest"]["models"].append({
        "id": m["id"],
        "name": m.get("name", m["id"]),
        "contextWindow": m.get("context_window", 128000),
        "maxTokens": m.get("max_tokens", 16384),
        "reasoning": m.get("reasoning", False),
        "input": m.get("input", ["text"]),
        "cost": {
            "input": m.get("cost", {}).get("input", 0),
            "output": m.get("cost", {}).get("output", 0),
            "cacheRead": m.get("cost", {}).get("cacheRead", 0),
            "cacheWrite": m.get("cost", {}).get("cacheWrite", 0)
        }
    })

os.makedirs(os.path.expanduser("~/.pi/agent"), exist_ok=True)
with open(os.path.expanduser("~/.pi/agent/models.json"), "w") as f:
    json.dump({"providers": providers}, f, indent=2)
```
