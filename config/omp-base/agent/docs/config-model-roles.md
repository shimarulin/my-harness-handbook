# Стратегия маршрутизации моделей Oh-My-Pi через KodikRouter

**Дата актуализации:** Сентябрь 2026 г.
**Платформа:** Oh-My-Pi (OMP)
**API-шлюз:** KodikRouter (тарификация: цена провайдера + 10% за маршрутизацию, PII-маскирование и фолбэки).

## 1. Ключевые принципы архитектуры

1. **Нет «серебряной пули»:** Маршрутизация должна строго соответствовать архитектурным особенностям модели и требованиям конкретной роли.
2. **Экономика «налога на размышления» (Thinking Tax):** Модели с принудительным режимом размышлений (например, `kimi-k2.7-code`) генерируют дополнительные скрытые выходные токены. Хотя OMP теперь корректно обрабатывает их вызовы инструментов (автоматически понижая `tool_choice` до `"auto"` благодаря PR #2547 и #13248), использование таких моделей для высокоитеративных задач (`task`, `designer`, `sonic`) экономически нецелесообразно.
3. **Приоритет контекста и мультимодальности:** Для задач анализа (`vision`, `designer`) критически важны нативная поддержка изображений и большое контекстное окно (1M+ токенов).
4. **Стабильность важнее «бесплатности»:** Модели с пометкой `:free` в агрегаторах имеют непредсказуемые RPM-лимиты и низкий приоритет в очереди. В продакшене они исключены в пользу стабильных дешевых альтернатив.
5. **Отказоустойчивость через фолбэки:** В конфигурации OMP всегда используются массивы моделей для автоматического переключения при исчерпании лимитов или сбоях.

## 3. Стратегии промпт-инжиниринга

Выбор модели диктует стиль общения с ней. Неправильный промпт ведет к перерасходу токенов или галлюцинациям.

### Для итеративных ролей с записью файлов (`@designer`, `@task`, `@sonic`)
* **Модели:** `minimax-m3`, `glm-5.3-flash`
* **Стиль:** Декларативный, ограничивающий, структурированный.
* **Запрещено:** Фразы-усилители вроде «подумай глубже», «предложи 3 варианта и сравни их» (увеличивают расход токенов в 2-7 раз без прироста качества).
* **Шаблон:**
  1. *Scope:* Какие файлы менять.
  2. *Acceptance Criteria:* Конкретные требования (адаптив, дизайн-система).
  3. *Stop Condition:* Четкое указание, когда остановиться (не запускать тесты, не менять пакеты).

### Для ролей глубокого анализа (`@slow`, `@advisor`)
* **Модели:** `kimi-k2.7-code`, `kimi-k3`
* **Стиль:** Провоцирующий глубокие рассуждения.
* **Разрешено и поощряется:** Явные запросы на пошаговый анализ, построение логических цепочек и проверку граничных условий.
* **Шаблон:** «Действуй как старший специалист по безопасности. Проанализируй код пошагово. Сначала выяви уязвимости, затем оцени архитектурные риски. Для каждой проблемы опиши цепочку рассуждений, которая привела к выводу, и предложи патч».

## 4. Финальная конфигурация `.omp/config.yaml`

```yaml
# Конфигурация ролей Oh-My-Pi для KodikRouter
# Примечание: OMP корректно обрабатывает модели с mandatory thinking (kimi-k2.7-code),
# автоматически понижая tool_choice до "auto" при необходимости (PR #2547, #13248).
# Однако из-за "налога на размышления" они используются преимущественно там,
# где глубокий анализ оправдывает стоимость (slow, advisor), или как фолбэк для сложных задач (task).

modelRoles:
  # Основная работа: стабильность в долгих сессиях, 1.31M контекст
  default:
    - kodikrouter/z-ai/glm-5.3-flash
    - kodikrouter/deepseek/deepseek-v4.1-flash

  # Быстрые утилитарные read-only задачи (scout, librarian)
  smol:
    - kodikrouter/z-ai/glm-5.3-flash
    - kodikrouter/qwen/qwen3.8-flash

  # Глубокий анализ и ревью (reviewer, security-reviewer)
  slow:
    - kodikrouter/moonshotai/kimi-k2.7-code
    - kodikrouter/qwen/qwen3.8-max

  # Архитектурное планирование
  plan:
    - kodikrouter/z-ai/glm-5.3
    - kodikrouter/deepseek/deepseek-v4.1-flash

  # Анализ изображений, схем, документов
  # Порядок: M3 первым (дешевле в 10 раз, сильнее в MMMU-Pro/OmniDocBench),
  # K3 как фолбэк для сложных visual reasoning задач
  vision:
    - kodikrouter/minimax/minimax-m3
    - kodikrouter/qwen/qwen3.8-flash
    - kodikrouter/moonshotai/kimi-k3

  # UI/UX реализация (без mandatory thinking ради скорости итераций)
  designer:
    - kodikrouter/minimax/minimax-m3
    - kodikrouter/z-ai/glm-5.3-flash

  # Независимый финальный аудит
  advisor:
    - kodikrouter/moonshotai/kimi-k3

  # Многошаговые субагентские задачи
  # glm-5.3-flash как основная рабочая лошадка; kimi-k2.7-code как фолбэк для сложных алгоритмических тупиков.
  task:
    - kodikrouter/z-ai/glm-5.3-flash
    - kodikrouter/minimax/minimax-m3
    - kodikrouter/moonshotai/kimi-k2.7-code

  # Механические и фоновые задачи
  sonic:
    - kodikrouter/z-ai/glm-5.3-flash
    - kodikrouter/qwen/qwen3.8-flash

  tiny:
    - kodikrouter/z-ai/glm-5.3-flash
    - kodikrouter/qwen/qwen3.8-flash

# Жёсткая привязка агентов к ролям для стабильности поведения
task:
  agentModelOverrides:
    reviewer: "@slow"
    security-reviewer: "@slow"
    scout: "@smol"
    librarian: "@smol"
    designer: "@designer"
    sonic: "@sonic"
    task: "@task"
```

## 5. Триггеры для пересмотра стратегии и известные ограничения

1. **Архитектурные изменения OMP:** Текущая стратегия опирается на то, что OMP корректно обрабатывает `tool_choice: "auto"` для моделей с mandatory thinking (PR #2547, #13248). Если будущие обновления изменят это поведение, потребуется пересмотр ролей `task` и `designer`.
2. **Аномалии тарификации:** В текущем дампе API выявлено, что `glm-5.3-flash:batch` ($0.72/$2.40) **дороже** обычной версии ($0.15/$0.50). До выяснения причин у поддержки KodikRouter использовать batch-варианты в продакшене запрещено.
3. **Изменение ценовой политики:** Если KodikRouter или провайдеры изменят цены более чем на 20%.
4. **Выход новых моделей:** Появление моделей, которые превосходят `kimi-k2.7-code` в код-ревью или `minimax-m3` в мультимодальности при сопоставимой цене, и при этом не имеют "налога на размышления".
