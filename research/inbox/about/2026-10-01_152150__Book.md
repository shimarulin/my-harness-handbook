# Анатомия harness

## Зачем эта глава

Ты уже запускал harness — Cursor, Claude Code, aider, свой скрипт на Python. Возможно, даже собирал что-то работающее. Но когда система начинает сбоить на реальных задачах, становится непонятно, **где именно проблема**: в промпте? в tools? в памяти? в цикле?

Эта глава разбирает harness как систему с четкими компонентами и границами ответственности. После неё ты сможешь:
- Диагностировать проблемы по симптомам
- Осознанно выбирать между готовыми harness (Cursor vs Claude Code vs свой)
- Собирать свои harness из правильных блоков

## Определение

**Harness** — это инфраструктура вокруг LLM, которая превращает одиночный вызов модели в итеративный процесс решения задачи.

```
┌─────────────────────────────────────┐
│           HARNESS                    │
│  ┌───────────────────────────────┐  │
│  │     ЦИКЛ (Loop)                │  │
│  │  perceive → plan → act →      │  │
│  │  observe → repeat              │  │
│  └───────────────────────────────┘  │
│         ↓              ↑             │
│  ┌──────────┐    ┌──────────┐       │
│  │ КОНТЕКСТ │    │  TOOLS   │       │
│  │          │    │          │       │
│  │ что      │    │ что      │       │
│  │ модель   │    │ модель   │       │
│  │ видит    │    │ делает   │       │
│  └──────────┘    └──────────┘       │
│         ↓              ↓             │
│  ┌──────────┐    ┌──────────┐       │
│  │  ПАМЯТЬ  │    │ ПЛАНИР.  │       │
│  │          │    │          │       │

## Пять компонентов

### 1. Контекст (Context)

**Что это:** Всё, что попадает в prompt на каждом шаге цикла.

**Что внутри:**
- System prompt (инструкции, роль, ограничения)
- История разговора (user/assistant messages)
- Результаты предыдущих tool calls
- Внешние данные (файлы, результаты поиска, ADR)
- Текущий план и прогресс

**Почему это важно:**
Модель **не имеет памяти между вызовами**. Каждый раз она видит только то, что лежит в контексте **сейчас**. Если ты что-то не положил в контекст — для модели этого не существует.

```python
# Плохо: модель не знает, что было раньше
messages = [
    {"role": "user", "content": "Продолжай"}
]

# Хорошо: модель видит всю историю
messages = [
    {"role": "system", "content": "Ты code reviewer..."},
    {"role": "user", "content": "Проверь этот PR"},
    {"role": "assistant", "content": "Я проверил, вот issues..."},
    {"role": "user", "content": "Продолжай"}
]
```

**Границы компонента:**
Контекст — это **только то, что в prompt**. Векторная база данных — это не контекст, это Extension. Контекст — это результат retrieval из этой базы.

### 2. Tools (Инструменты)

**Что это:** Функции, которые модель может вызвать для взаимодействия с внешним миром.

**Что внутри:**
- Схема (JSON Schema): имя, параметры, описание
- Реализация: Python/JS функция
- Обработка ошибок и retry-логика
- Логирование вызовов

**Почему это важно:**
Без tools модель — это просто текстовый генератор. Tools превращают её в агента, который может читать файлы, выполнять код, делать HTTP-запросы, писать в базу данных.

```python
# Описание tool для модели
tools = [
    {
        "type": "function",
        "function": {
            "name": "read_file",
            "description": "Read contents of a file",
            "parameters": {
                "type": "object",
                "properties": {
                    "path": {
                        "type": "string",
                        "description": "Path to file"
                    }
                },
                "required": ["path"]
            }
        }
    }
]

# Реализация
def read_file(path: str) -> str:
    with open(path, 'r') as f:
        return f.read()
```

**Границы компонента:**
Tool — это **только то, что модель может вызвать**. Векторная база — не tool, пока ты не обернул её в функцию `search_knowledge_base(query)`. MCP-сервер — это коллекция tools.

### 3. Память (Memory)

**Что это:** Механизм сохранения информации между шагами цикла и между сессиями.

**Что внутри:**
- **Short-term:** История разговора в рамках одной задачи
- **Long-term:** База знаний, предыдущие решения, паттерны ошибок
- **Working memory:** Текущий план, прогресс, промежуточные результаты
- **Episodic memory:** Конкретные случаи решения похожих задач

**Почему это важно:**
Контекстное окно ограничено (128K токенов у Claude, 1M у Gemini). Реальные задачи требуют больше контекста. Память решает проблему "что помнить, что забыть".

```python
class Memory:
    def __init__(self):
        self.short_term = []  # последние N сообщений
        self.long_term = VectorDB()  # все знания
        self.working = {}  # текущий план
    
    def save(self, message):
        self.short_term.append(message)
        if len(self.short_term) > 100:
            # Суммаризируем старое
            summary = summarize(self.short_term[:50])
            self.long_term.store(summary)
            self.short_term = self.short_term[50:]
    
    def load(self, query=None):
        context = self.short_term.copy()
        if query:
            # Добавляем релевантное из long-term
            relevant = self.long_term.search(query)
            context.extend(relevant)
        return context
```

**Границы компонента:**
Память — это **механизм управления контекстом**. Сама векторная база — это Extension. Память решает, что из базы положить в контекст.

### 4. Планирование (Planning)

**Что это:** Механизм декомпозиции сложной задачи на подзадачи.

**Что внутри:**
- Plan mode: явный шаг планирования перед действием
- Todo-списки: список подзадач с статусами
- Re-planning: корректировка плана при ошибках
- Декомпозиция: разбиение на атомарные шаги

**Почему это важно:**
Модели плохо решают сложные задачи за один шаг. Планирование позволяет:
- Разбить задачу на понятные шаги
- Отслеживать прогресс
- Возвращаться к предыдущим шагам при ошибках
- Объяснять пользователю, что происходит

```python
class Planner:
    def create_plan(self, task: str, context: list) -> list:
        # Модель генерирует план
        response = llm.chat([
            {"role": "system", "content": "Create a step-by-step plan"},
            {"role": "user", "content": f"Task: {task}\nContext: {context}"}
        ])
        
        plan = parse_plan(response)
        return plan  # [{"step": 1, "action": "...", "status": "pending"}, ...]
    
    def update_plan(self, plan: list, step_result: dict) -> list:
        # Обновляем статус текущего шага
        current = next(s for s in plan if s["status"] == "in_progress")
        current["status"] = "done" if step_result["success"] else "failed"
        
        # Если шаг провалился, перепланируем
        if not step_result["success"]:
            plan = self.replan(plan, step_result)
        
        return plan
```

**Границы компонента:**
Планирование — это **стратегия**. Конкретные действия (tool calls) — это уже цикл.

### 5. Контроль (Control)

**Что это:** Условия остановки и ограничения агента.

**Что внутри:**
- Условия успеха: как понять, что задача решена
- Условия ошибки: когда остановиться с ошибкой
- Бюджеты: лимиты по шагам, времени, токенам, деньгам
- Guardrails: запретные действия
- Human-in-the-loop: обязательные подтверждения

**Почему это важно:**
Агент без контроля может:
- Бесконечно зацикливаться
- Потратить весь бюджет на одну задачу
- Выполнить опасное действие (удалить прод-базу)
- Галлюцинировать "успех" когда его нет

```python
class Control:
    def __init__(self, max_steps=50, max_cost=10.0):
        self.max_steps = max_steps
        self.max_cost = max_cost
        self.steps = 0
        self.cost = 0.0
    
    def should_continue(self, context: list) -> bool:
        # Проверка бюджетов
        if self.steps >= self.max_steps:
            return False
        if self.cost >= self.max_cost:
            return False
        
        # Проверка успеха
        last_message = context[-1]
        if self.is_task_complete(last_message):
            return False
        
        return True
    
    def is_task_complete(self, message: dict) -> bool:
        # Модель сама оценивает, решена ли задача
        response = llm.chat([
            {"role": "system", "content": "Is the task complete? Answer yes/no"},
            {"role": "user", "content": message["content"]}
        ])
        return "yes" in response.lower()
```

**Границы компонента:**
Контроль — это **ограничения**. Guardrails (безопасность) — часть контроля. Observability (логирование) — не контроль, это Extension.

## Как компоненты взаимодействуют

```
Шаг цикла:

1. PERCEIVE (восприятие)
   - Memory.load() → загружает контекст
   - Control.should_continue() → проверяет бюджеты
   ↓
2. PLAN (планирование)
   - Planner.create_plan() или Planner.update_plan()
   - Модель решает, что делать дальше
   ↓
3. ACT (действие)
   - Модель выбирает tool
   - Tool.execute() → выполняет действие
   ↓
4. OBSERVE (наблюдение)
   - Результат tool добавляется в контекст
   - Memory.save() → сохраняет в память
   - Control.update_cost() → обновляет метрики
   ↓
5. REPEAT или STOP
   - Control.should_continue() → решение о продолжении
```

## Где проходит граница между harness и внешними системами

Это важный вопрос, который часто вызывает путаницу.

| Компонент | Harness | Extension |
|-----------|---------|-----------|
| **Context** | То, что в prompt | Vector DB, Graph DB (источники данных) |
| **Tools** | Схема + вызов | MCP-сервер, API (реализация) |
| **Memory** | Механизм управления | Vector store (хранилище) |
| **Planning** | Логика декомпозиции | - |
| **Control** | Условия остановки | Observability (метрики) |

**Пример:**
- **Vector DB** (Qdrant, Pinecone) — это Extension
- **Функция `search_knowledge_base(query)`** — это Tool в Harness
- **Логика "когда искать, что класть в контекст"** — это Memory в Harness

## Антипаттерны

### Антипаттерн 1: "Всё в контексте"

**Симптом:** Промпт на 100K токенов, модель "теряется" и галлюцинирует.

**Причина:** Попытка положить в контекст всё сразу вместо умного retrieval.

**Решение:** Memory должен решать, что класть в контекст на каждом шаге, а не грузить всё upfront.

### Антипаттерн 2: "Tool без описания"

**Симптом:** Модель не вызывает tool или вызывает неправильно.

**Причина:** Плохое description в схеме tool. Модель не понимает, когда и зачем использовать.

**Решение:** Описание tool — это промпт. Пиши подробно: когда использовать, какие параметры, что возвращает.

### Антипаттерн 3: "Нет контроля"

**Симптом:** Агент зацикливается или тратит весь бюджет.

**Причина:** Нет max_steps, max_cost, условий остановки.

**Решение:** Всегда ставь бюджеты и условия успеха/ошибки.

### Антипаттерн 4: "Память = история сообщений"

**Симптом:** На длинных задачах модель "забывает" начало разговора.

**Причина:** Память — это просто append в список, без суммаризации и prioritization.

**Решение:** Memory должен суммаризировать старое, хранить важное отдельно, делать retrieval по запросу.

"""
Минимальная реализация Agent Harness с 5 компонентами:
- Context (контекст)
- Tools (инструменты)
- Memory (память)
- Planning (планирование)
- Control (контроль)

Запуск: python examples/harness/anatomy.py
"""

import json
from typing import List, Dict, Any, Callable
from dataclasses import dataclass


# ============================================================================
# 1. CONTEXT - что модель видит на каждом шаге
# ============================================================================

@dataclass
class Message:
    role: str  # "system", "user", "assistant", "tool"
    content: str
    tool_call_id: str = None
    name: str = None


class Context:
    """Управляет тем, что попадает в prompt."""
    
    def __init__(self, system_prompt: str):
        self.messages: List[Message] = [
            Message(role="system", content=system_prompt)
        ]
    
    def add_user_message(self, content: str):
        self.messages.append(Message(role="user", content=content))
    
    def add_assistant_message(self, content: str):
        self.messages.append(Message(role="assistant", content=content))
    
    def add_tool_result(self, tool_call_id: str, result: str, name: str):
        self.messages.append(Message(
            role="tool",
            content=result,
            tool_call_id=tool_call_id,
            name=name
        ))
    
    def get_messages(self) -> List[Dict]:
        """Формат для API."""
        return [
            {
                "role": m.role,
                "content": m.content,
                **({"tool_call_id": m.tool_call_id} if m.tool_call_id else {}),
                **({"name": m.name} if m.name else {})
            }
            for m in self.messages
        ]


# ============================================================================
# 2. TOOLS - что модель может делать
# ============================================================================

class ToolRegistry:
    """Реестр доступных инструментов."""
    
    def __init__(self):
        self.tools: Dict[str, Callable] = {}
        self.schemas: List[Dict] = []
    
    def register(self, name: str, description: str, parameters: Dict, func: Callable):
        """Регистрирует tool."""
        self.tools[name] = func
        self.schemas.append({
            "type": "function",
            "function": {
                "name": name,
                "description": description,
                "parameters": parameters
            }
        })
    
    def execute(self, name: str, arguments: Dict) -> str:
        """Выполняет tool."""
        if name not in self.tools:
            return f"Error: Tool '{name}' not found"
        
        try:
            result = self.tools[name](**arguments)
            return str(result)
        except Exception as e:
            return f"Error executing {name}: {str(e)}"


# Пример tools
def read_file(path: str) -> str:
    """Read file contents."""
    try:
        with open(path, 'r') as f:
            return f.read()
    except FileNotFoundError:
        return f"File not found: {path}"


def calculate(expression: str) -> str:
    """Evaluate math expression."""
    try:
        # В продакшене используй безопасный evaluator
        result = eval(expression, {"__builtins__": {}})
        return str(result)
    except Exception as e:
        return f"Error: {str(e)}"


# ============================================================================
# 3. MEMORY - что сохраняется между шагами
# ============================================================================

class Memory:
    """Управляет памятью агента."""
    
    def __init__(self, max_history: int = 50):
        self.max_history = max_history
        self.working_memory: Dict[str, Any] = {}  # Текущий план, прогресс
    
    def load_context(self, context: Context) -> Context:
        """Загружает релевантный контекст."""
        # В простой версии просто возвращаем context как есть
        # В продвинутой - добавляем из long-term memory
        return context
    
    def save_step(self, context: Context):
        """Сохраняет шаг в память."""
        # Обрезаем историю если слишком длинная
        if len(context.messages) > self.max_history:
            # Оставляем system prompt + последние N сообщений
            context.messages = (
                context.messages[:1] +  # system prompt
                context.messages[-(self.max_history-1):]
            )
    
    def set_working_memory(self, key: str, value: Any):
        """Устанавливает значение в working memory."""
        self.working_memory[key] = value
    
    def get_working_memory(self, key: str) -> Any:
        """Получает значение из working memory."""
        return self.working_memory.get(key)


# ============================================================================
# 4. PLANNING - как декомпозировать задачу
# ============================================================================

class Planner:
    """Управляет планированием."""
    
    def should_plan(self, task: str) -> bool:
        """Определяет, нужен ли явный план."""
        # Простые задачи не требуют планирования
        complex_keywords = ["многошаговая", "сложная", "несколько", "все"]
        return any(kw in task.lower() for kw in complex_keywords)
    
    def create_plan(self, task: str, context: Context) -> List[Dict]:
        """Создает план выполнения."""
        # В реальности здесь вызов LLM для генерации плана
        # Для примера возвращаем простой план
        return [
            {"step": 1, "action": "analyze", "status": "pending"},
            {"step": 2, "action": "execute", "status": "pending"},
            {"step": 3, "action": "verify", "status": "pending"}
        ]
    
    def update_plan(self, plan: List[Dict], step_result: Dict) -> List[Dict]:
        """Обновляет план после шага."""
        # Находим текущий шаг и обновляем статус
        for step in plan:
            if step["status"] == "pending":
                step["status"] = "done" if step_result.get("success") else "failed"
                break
        return plan


# ============================================================================
# 5. CONTROL - когда остановиться
# ============================================================================

class Control:
    """Управляет условиями остановки и ограничениями."""
    
    def __init__(self, max_steps: int = 20, max_cost: float = 5.0):
        self.max_steps = max_steps
        self.max_cost = max_cost
        self.steps = 0
        self.cost = 0.0
    
    def should_continue(self, context: Context) -> bool:
        """Проверяет, нужно ли продолжать."""
        # Проверка бюджетов
        if self.steps >= self.max_steps:
            print(f"[Control] Stopped: max steps ({self.max_steps}) reached")
            return False
        
        if self.cost >= self.max_cost:
            print(f"[Control] Stopped: max cost (${self.max_cost}) reached")
            return False
        
        # Проверка завершения задачи
        if self.is_task_complete(context):
            print("[Control] Stopped: task completed")
            return False
        
        return True
    
    def is_task_complete(self, context: Context) -> bool:
        """Проверяет, решена ли задача."""
        # В реальности здесь вызов LLM для оценки
        # Для примера проверяем наличие финального ответа
        if not context.messages:
            return False
        
        last_message = context.messages[-1]
        if last_message.role == "assistant":
            # Если последнее сообщение от ассистента и не содержит tool_calls
            # считаем задачу завершенной
            return "tool_calls" not in str(last_message)
        
        return False
    
    def record_step(self, cost: float):
        """Записывает метрики шага."""
        self.steps += 1
        self.cost += cost

class AgentHarness:
    """Полный harness с 5 компонентами."""
    
    def __init__(
        self,
        llm_client,  # Ваш LLM client (OpenAI, Anthropic, etc.)
        system_prompt: str,
        tools: ToolRegistry,
        max_steps: int = 20,
        max_cost: float = 5.0
    ):
        self.llm = llm_client
        
        # Инициализация 5 компонентов
        self.context = Context(system_prompt)
        self.tools = tools
        self.memory = Memory()
        self.planner = Planner()
        self.control = Control(max_steps, max_cost)
    
    def run(self, task: str) -> str:
        """Запускает цикл выполнения задачи."""
        print(f"[Harness] Starting task: {task}")
        
        # Добавляем задачу в контекст
        self.context.add_user_message(task)
        
        # Возможно создаем план
        if self.planner.should_plan(task):
            plan = self.planner.create_plan(task, self.context)
            self.memory.set_working_memory("plan", plan)
            print(f"[Harness] Created plan with {len(plan)} steps")
        
        # Основной цикл
        while self.control.should_continue(self.context):
            print(f"\n[Harness] Step {self.control.steps + 1}")
            
            # 1. PERCEIVE - загружаем контекст
            self.context = self.memory.load_context(self.context)
            
            # 2. PLAN + ACT - вызываем LLM
            response = self.llm.chat.completions.create(
                model="gpt-4",
                messages=self.context.get_messages(),
                tools=self.tools.schemas,
                tool_choice="auto"
            )
            
            message = response.choices[0].message
            
            # Обновляем стоимость
            cost = self._calculate_cost(response.usage)
            self.control.record_step(cost)
            
            # 3. OBSERVE - обрабатываем ответ
            if message.tool_calls:
                # Модель хочет вызвать tools
                self.context.add_assistant_message(message.content or "")
                
                for tool_call in message.tool_calls:
                    print(f"[Harness] Calling tool: {tool_call.function.name}")
                    
                    # Выполняем tool
                    arguments = json.loads(tool_call.function.arguments)
                    result = self.tools.execute(tool_call.function.name, arguments)
                    
                    print(f"[Harness] Tool result: {result[:100]}...")
                    
                    # Добавляем результат в контекст
                    self.context.add_tool_result(
                        tool_call.id,
                        result,
                        tool_call.function.name
                    )
            else:
                # Модель дала финальный ответ
                self.context.add_assistant_message(message.content)
                print(f"[Harness] Final answer: {message.content[:100]}...")
                break
            
            # 4. SAVE - сохраняем шаг в память
            self.memory.save_step(self.context)
        
        # Возвращаем последний ответ
        return self.context.messages[-1].content
    
    def _calculate_cost(self, usage) -> float:
        """Рассчитывает стоимость вызова."""
        # Пример для GPT-4: $0.03/1K input, $0.06/1K output
        input_cost = (usage.prompt_tokens / 1000) * 0.03
        output_cost = (usage.completion_tokens / 1000) * 0.06
        return input_cost + output_cost

class AdvancedMemory:
    """Продвинутая память с short-term и long-term компонентами."""
    
    def __init__(self, collection_name: str = "agent_memory"):
        # Short-term: просто список сообщений
        self.short_term: List[Dict] = []
        self.max_short_term = 50
        
        # Long-term: vector database
        self.chroma_client = chromadb.Client(Settings(
            chroma_db_impl="duckdb+parquet",
            persist_directory="./chroma_db"
        ))
        self.collection = self.chroma_client.get_or_create_collection(
            name=collection_name,
            metadata={"hnsw:space": "cosine"}
        )
        
        # Working memory: текущий план и прогресс
        self.working: Dict[str, Any] = {}
    
    def add_message(self, message: Dict):
        """Добавляет сообщение в short-term memory."""
        self.short_term.append(message)
        
        # Если история слишком длинная, суммаризируем старое
        if len(self.short_term) > self.max_short_term:
            self._summarize_old_messages()
    
    def store_in_long_term(self, content: str, metadata: Dict = None):
        """Сохраняет важную информацию в long-term memory."""
        doc_id = f"mem_{len(self.collection.get()['ids'])}"
        self.collection.add(
            documents=[content],
            metadatas=[metadata or {}],
            ids=[doc_id]
        )
        logger.info(f"Stored in long-term memory: {content[:50]}...")
    
    def retrieve_relevant(self, query: str, k: int = 3) -> List[str]:
        """Извлекает релевантную информацию из long-term memory."""
        results = self.collection.query(
            query_texts=[query],
            n_results=k
        )
        return results['documents'][0] if results['documents'] else []
    
    def get_context(self, current_query: str = None) -> List[Dict]:
        """Возвращает полный контекст для LLM."""
        context = self.short_term.copy()
        
        # Добавляем релевантное из long-term
        if current_query and len(self.collection.get()['ids']) > 0:
            relevant = self.retrieve_relevant(current_query)
            for doc in relevant:
                context.append({
                    "role": "system",
                    "content": f"[Relevant memory]: {doc}"
                })
        
        return context
    
    def _summarize_old_messages(self):
        """Суммаризирует старые сообщения и переносит в long-term."""
        old_messages = self.short_term[:len(self.short_term)//2]
        self.short_term = self.short_term[len(self.short_term)//2:]
        
        # Создаем резюме
        summary = f"Previous conversation summary: {len(old_messages)} messages exchanged"
        self.store_in_long_term(summary, {"type": "conversation_summary"})
    
    def set_plan(self, plan: List[Dict]):
        """Устанавливает текущий план."""
        self.working['plan'] = plan
    
    def get_plan(self) -> Optional[List[Dict]]:
        """Возвращает текущий план."""
        return self.working.get('plan')
    
    def update_plan_step(self, step_index: int, status: str, result: str = None):
        """Обновляет статус шага плана."""
        plan = self.get_plan()
        if plan and step_index < len(plan):
            plan[step_index]['status'] = status
            if result:
                plan[step_index]['result'] = result

class AdvancedPlanner:
    """Планировщик с явной декомпозицией задач."""
    
    def __init__(self, llm_client: OpenAI):
        self.llm = llm_client
    
    def needs_planning(self, task: str) -> bool:
        """Определяет, требует ли задача явного планирования."""
        # Промпт для оценки сложности
        response = self.llm.chat.completions.create(
            model="gpt-4",
            messages=[
                {
                    "role": "system",
                    "content": "Определи, требует ли задача явного планирования. "
                               "Ответь только 'yes' или 'no'."
                },
                {
                    "role": "user",
                    "content": f"Задача: {task}\n\n"
                               "Требует планирования (много шагов, сложная)?"
                }
            ],
            temperature=0
        )
        
        answer = response.choices[0].message.content.strip().lower()
        return answer == "yes"
    
    def create_plan(self, task: str, context: List[Dict]) -> List[Dict]:
        """Создает детальный план выполнения задачи."""
        response = self.llm.chat.completions.create(
            model="gpt-4",
            messages=[
                {
                    "role": "system",
                    "content": "Создай пошаговый план выполнения задачи. "
                               "Верни JSON массив объектов с полями: "
                               "step (int), action (string), status (always 'pending')"
                },
                {
                    "role": "user",
                    "content": f"Задача: {task}\nКонтекст: {json.dumps(context[-5:], ensure=False)}"
                }
            ],
            response_format={"type": "json_object"},
            temperature=0
        )
        
        plan_data = json.loads(response.choices[0].message.content)
        plan = plan_data.get('plan', plan_data.get('steps', []))
        
        logger.info(f"Created plan with {len(plan)} steps")
        return plan
    
    def replan(self, plan: List[Dict], failed_step: Dict, error: str) -> List[Dict]:
        """Перепланирует после ошибки."""
        response = self.llm.chat.completions.create(
            model="gpt-4",
            messages=[
                {
                    "role": "system",
                    "content": "Шаг плана провалился. Предложи новый план. "
                               "Верни JSON массив новых шагов."
                },
                {
                    "role": "user",
                    "content": f"Проваленный шаг: {json.dumps(failed_step)}\n"
                               f"Ошибка: {error}\n"
                               f"Текущий план: {json.dumps(plan)}"
                }
            ],
            response_format={"type": "json_object"},
            temperature=0
        )
        
        new_plan_data = json.loads(response.choices[0].message.content)
        return new_plan_data.get('plan', [])
