## Рекомендация

Для серии технических руководств со сложной разметкой оптимальная связка — **markdownlint-cli2 для структурной валидации + textlint для проверки текста**. markdownlint-cli2 — наиболее зрелый инструмент с 53 правилами, автофиксом (`--fix`) и глубокой интеграцией в VS Code, GitHub Actions и pre-commit【turn10click0】. Он корректно обрабатывает GFM-таблицы, блоки кода и frontmatter. textlint дополняет его проверкой стиля письма, терминологии и грамматики【turn8search2】.

Если важна максимальная скорость и единый бинарник без Node.js — рассмотрите **rumdl** (реализует все правила markdownlint плюс 35 дополнительных, включая проверку относительных ссылок и TOC)【turn11fetch0】.

## Почему markdownlint-cli2 для технических руководств

### Ключевые правила для сложной разметки

| Правило | Что проверяет | Зачем для техгайдов |
|---|---|---|
| **MD001** | Заголовки инкрементируются по одному уровню | Корректная навигация, скринридеры【turn14fetch0】 |
| **MD025** | Один H1 на файл | Чёткая структура документа【turn14fetch0】 |
| **MD036** | Не использовать эмфаз вместо заголовков | Семантическая правильность【turn14fetch0】 |
| **MD040** | Язык для fenced-кода | Синтаксическая подсветка в рендерах【turn14fetch0】 |
| **MD041** | Первая строка — H1 | Единообразное начало【turn14fetch0】 |
| **MD013** | Длина строки | Читаемость в diff |
| **MD022** | Пустые строки вокруг заголовков | Предсказуемый рендеринг【turn14fetch0】 |
| **MD031** | Пустые строки вокруг блоков кода | Корректный парсинг【turn14fetch0】 |
| **MD032** | Пустые строки вокруг списков | Корректный парсинг【turn14fetch0】 |
| **MD047** | Файл заканчивается newline | POSIX-совместимость【turn14fetch0】 |

## Практические конфигурации

### Файл `.markdownlint-cli2.jsonc`

Создайте в корне проекта:

```jsonc
{
  "config": {
    "default": true,
    "MD013": { "line_length": 120 },
    "MD024": { "siblings_only": true },
    "MD033": false,
    "MD041": false
  },
  "globs": ["**/*.md"],
  "ignores": ["node_modules/**", "vendor/**"]
}
```

- `MD013` с длиной 120 символов — комфортно для техтекстов с кодом.
- `MD024` с `siblings_only: true` — разрешает одинаковые заголовки на разных уровнях.
- `MD033` отключено — в техгайдах часто нужны HTML-вставки.
- `MD041` отключено, если frontmatter идёт перед первым заголовком.

Примеры реальных конфигураций в open-source: <https://git.theoludwig.fr/theoludwig/.profile>.profile/.markdownlint-cli2.jsonc【turn7search2】, <https://git.farh.net>【turn22search0】.

### Интеграция в pre-commit

`.pre-commit-config.yaml`:

```yaml
repos:
  - repo: https://github.com/DavidAnson/markdownlint-cli2
    rev: v0.23.2
    hooks:
      - id: markdownlint-cli2
        args: ["--fix"]
```

markdownlint-cli2 официально поддерживается pre-commit【turn17search1】. Пример из реального проекта: <https://gitlab.developers.cam.ac.uk>【turn2search3】.

### Интеграция в GitHub Actions

`.github/workflows/lint.yml`:

```yaml
name: Markdown Lint
on: [push, pull_request]

jobs:
  markdownlint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: DavidAnson/markdownlint-cli2-action@v16
        with:
          globs: '**/*.md'
          config: 'config/custom.markdownlint.jsonc'
```

Официальный Action: <https://github.com/DavidAnson/markdownlint-cli2-action>【turn6search3】【turn9search0】.

### VS Code расширение

Установите `markdownlint` (DavidAnson) из Marketplace: <https://marketplace.visualstudio.com/items?itemName=DavidAnson.vscode-markdownlint>【turn0search7】. Расширение автоматически подхватывает `.markdownlint-cli2.jsonc` и показывает ошибки в реальном времени.

### Запуск из CLI

```bash
# Установка глобально
npm install -g markdownlint-cli2

# Проверка с автофиксом
markdownlint-cli2 --fix "**/*.md"

# Проверка без фикса
markdownlint-cli2 "**/*.md"

# С кастомным конфигом
markdownlint-cli2 --config config/custom.markdownlint.jsonc "**/*.md"
```

Пример из GitLab Handbook: `markdownlint-cli2 --config tasks/task.markdownlint-cli2.jsonc **/*.md --fix`【turn25fetch0】.

## Дополнение: textlint для проверки текста

Для валидации стиля текста (не структуры) добавьте textlint:

`.textlintrc.json`:

```json
{
  "rules": {
    "max-comma": true,
    "sentence-length": {
      "max": 100
    },
    "no-doubled-conjunction": true,
    "no-start-duplicated-conjunction": true,
    "period-in-list-item": true,
    "common-misspellings": true
  }
}
```

textlint — «подключаемый линтер для естественного языка и Markdown», вдохновлённый ESLint【turn8search2】【turn6search2】. Устанавливается через `npm install -g textlint` и запускается `textlint "**/*.md"`.

Ресурсы: <https://github.com/textlint/textlint>, контейнерная версия: <https://github.com/uhooi/docker-textlint>【turn6search1】.

## Альтернативы: когда выбрать другое

| Сценарий | Инструмент | Причина |
|---|---|---|
| Максимальная скорость, нет Node.js | **rumdl** | Нативный Rust-бинарник, 217 мс vs 2.2 с у markdownlint-cli2【turn9fetch1】【turn12fetch0】 |
| Уже используете unified/remark | **remark-lint** | Единая экосистема с rehype, MDX【turn1fetch1】 |
| Python-проекты | **pymarkdown** | Если вся инфраструктура на Python【turn6search0】 |
| Только форматирование | **Prettier** | «Мнение-ориентированный» форматировщик без линтинга【turn10click0】 |

Сравнение всех инструментов: <https://rumdl.dev/comparison/>【turn10click0】.

## Типичные проблемы сложной разметки и решения

<details>
<summary><b>Вложенные блоки кода ломают парсер</b></summary>

Используйте 4+ обратных апострофа для внешнего блока, 3 для внутреннего. Правило MD070 в rumdl проверяет вложенные кодовые блоки【turn14fetch0】.

</details>

<details>
<summary><b>GFM-таблицы с длинным контентом</b></summary>

markdownlint-cli2 и rumdl поддерживают GFM-таблицы нативно【turn11fetch0】. Для форматирования таблиц используйте `rumdl fmt` или Prettier.

</details>

<details>
<summary><b>Frontmatter YAML не линтится</b></summary>

markdownlint пропускает frontmatter автоматически. Для проверки содержимого frontmatter используйте правило MD072 (frontmatter key sort) в rumdl【turn14fetch0】 или отдельные JSON Schema-валидаторы.

</details>

<details>
<summary><b>MD040 ругается на директивы MkDocs/MyST</b></summary>

Если используете MkDocs-директивы (` ```{toctree} `), отключите MD040 в конфиге или установите flavor = "mkdocs" в rumdl【turn2search0】【turn11fetch0】.

</details>
